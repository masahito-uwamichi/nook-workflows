
# ZipIR: Latent Pyramid Diffusion Transformer for High-Resolution Image Restoration

[View Paper](http://arxiv.org/abs/2504.08591v1)

## 1. 既存研究では何ができなかったのか

既存の研究、特にdiffusion modelを用いた画像復元は、セマンティックな詳細や局所的な忠実性の復元において優れた能力を発揮していましたが、超高解像度画像に適用する際に、品質と効率の間で深刻なトレードオフが生じていました。これは、長距離の注意機構(long-range attention mechanisms)の計算コストが非常に高いためです。つまり、高解像度画像に対して、十分な品質を保ちつつ、現実的な時間で処理することが困難でした。

## 2. どのようなアプローチでそれを解決しようとしたか

ZipIRは、高解像度画像の復元における効率、スケーラビリティ、長距離モデリングを向上させるための新しいフレームワークです。主なアプローチは以下の通りです。

*   **高圧縮潜在表現 (Highly Compressed Latent Representation):** 画像を32倍に圧縮する潜在表現を使用し、空間トークン数を効果的に削減しました。これにより、Diffusion Transformer (DiT)のような高容量モデルの使用が可能になります。
*   **Latent Pyramid VAE (LP-VAE):** 潜在空間をサブバンドに構造化するLP-VAEを提案しました。これにより、diffusion modelの学習を容易にしています。ピラミッド構造により、異なるスケールの特徴を効率的に捉えられます。
    ```python
    # LP-VAE の疑似コード
    def LP_VAE(image):
        # エンコード処理 (例: CNN)
        latent = encode(image)

        # 潜在空間をサブバンドに分割
        sub_bands = split_into_subbands(latent)

        # デコード処理 (例: 逆CNN)
        reconstructed_image = decode(sub_bands)

        return reconstructed_image, latent
    ```

## 3. 結果、何が達成できたのか

ZipIRは、最大2K解像度のフル画像で学習することで、既存のdiffusion modelベースの手法を上回り、深刻に劣化(degraded)した入力から高解像度画像を復元する際に、比類のない速度と品質を提供することに成功しました。 具体的には、以下の点が達成されました。

*   **高速化:** 潜在空間でdiffusion modelを適用することで、計算コストを大幅に削減し、高速な処理を実現しました。
*   **高画質化:** LP-VAEにより、高解像度画像の細部まで忠実に復元することが可能になりました。
*   **スケーラビリティ向上:** 高解像度画像への適用が容易になり、より大きな画像サイズへの対応が可能になりました。

## 4. Limitationや問題点は何か

本文で明示的に言及されている制限事項は、潜在空間での処理に起因する情報損失の可能性です。32xの圧縮率で潜在空間に落とし込む際に、どうしても情報が失われる可能性があります。

私が考える問題点としては、以下のものが挙げられます。

*   **LP-VAEの設計:** LP-VAEの構造は、特定の種類の画像に適している可能性がありますが、他の種類の画像では性能が低下する可能性があります。サブバンドの分割方法や、エンコーダ・デコーダのアーキテクチャが、最終的な復元品質に大きく影響するため、汎用性に課題が残る可能性があります。
*   **学習データへの依存:** 学習データと異なる種類の画像に対して、どの程度汎化できるかは不明です。特に、学習データに含まれない種類の劣化(degradation)に対しては、性能が低下する可能性があります。
*   **アーティファクトの発生:** 高圧縮の潜在空間を使用しているため、復元された画像にアーティファクトが発生する可能性があります。特に、非常に細かいテクスチャや構造を持つ画像では、アーティファクトが目立ちやすいかもしれません。
*   **計算資源:** 2K解像度での学習は、依然として大規模な計算資源を必要とする可能性があります。研究レベルでは問題なくても、一般ユーザーが手軽に利用できるレベルには至っていないかもしれません。

## 5. 技術的な詳細について

ZipIRの技術的な詳細は以下の通りです。

1.  **Latent Pyramid VAE (LP-VAE):**
    *   画像をエンコードして、圧縮された潜在表現を生成します。
    *   潜在空間を複数のサブバンドに分割し、異なるスケールの特徴を捉えます。
    *   サブバンドに分割された潜在表現をデコードして、画像を再構築します。
    *   VAEの損失関数（再構成損失とKLダイバージェンス）を用いて、エンコーダとデコーダを学習します。
2.  **Diffusion Transformer (DiT):**
    *   LP-VAEで生成された潜在表現に対して、Diffusion Transformerを適用します。
    *   DiTは、Transformerアーキテクチャをベースにしたdiffusion modelであり、潜在空間におけるノイズ除去プロセスを学習します。
    *   DiTの学習には、ノイズを加えた潜在表現から元の潜在表現を予測する目的関数を使用します。
3.  **全体のアーキテクチャ:**
    *   入力画像をLP-VAEで潜在空間にエンコードし、DiTでノイズ除去を行い、LP-VAEで元の画像空間にデコードします。
    *   LP-VAEとDiTは、エンドツーエンドで学習することで、高解像度画像の復元性能を最大化します。

Diffusion Transformer (DiT)のコア部分は通常のTransformerと同様ですが、diffusion model特有のノイズスケジュールの制御や、潜在空間での処理に合わせて最適化されています。 例えば、以下のような疑似コードで表現できます。

```python
# DiTの疑似コード
def DiT(latent, timestep):
  # タイムステップをTransformerに入力 (例: Embedding)
  time_embedding = time_embed(timestep)

  # Transformerブロックを複数回適用
  x = latent + time_embedding # タイムステップ情報を付加

  for block in transformer_blocks:
    x = block(x)

  # 最終的なノイズ予測
  predicted_noise = output_layer(x)

  return predicted_noise
```

# Do PhD-level LLMs Truly Grasp Elementary Addition? Probing Rule Learning vs. Memorization in Large Language Models

[View Paper](http://arxiv.org/abs/2504.05262v1)

## 1. 既存研究では何ができなかったのか

既存研究は、LLMの数学的推論能力を評価する際に、複雑なベンチマークに焦点を当てがちでした。これにより、LLMが高いスコアを出す一方で、基本的な算術原則の理解が不十分な場合があるという問題が見過ごされていました。

具体的には、以下の点が指摘されています。

*   **複雑な問題設定による基礎的理解の隠蔽:** GSM8kなどの複雑なベンチマークは、高度なパターンマッチング能力を評価する一方で、基本的な算術規則の理解を評価できていませんでした。複雑さゆえに、基礎的な数学的推論におけるギャップが隠蔽されてしまう可能性がありました。
*   **表面的な振る舞いの評価:** 既存研究の多くは、表面的な性能や特定のメカニズムに焦点を当てており、LLMが実際に算術の原則を理解しているのか、単にパターンを記憶しているのかを区別できていませんでした。
*   **記号表現に対する脆弱性:** LLMは、数値表現やトークン化に敏感であり、形式的な理解よりも表面的なフォーマットに依存している可能性がありました。
*   **真の理解とパターンマッチングの区別困難:** 既存の評価指標では、真の理解と高度なパターンマッチングを区別することが困難でした。

## 2. どのようなアプローチでそれを解決しようとしたか

本研究では、LLMの基本的な算術能力を厳密に評価するために、以下の3つの主要なアプローチを採用しました。

1.  **基本的な二整数加算を用いた評価:** 複雑なベンチマークの代わりに、最も基本的な演算である二整数加算（0から2<sup>64</sup>）に焦点を当てました。これにより、LLMの規則理解を直接的に評価することが可能になりました。

    *   **利点1:** 明確なアルゴリズム構造により、規則の理解を直接評価できます。
    *   **利点2:** 無限の問題空間（0から2<sup>64</sup>）により、純粋な記憶戦略を排除できます。
    *   **利点3:** 言語的な要素を排除し、純粋な算術能力を評価できます。
2.  **記号マッピングによる抽象化能力の評価:** 数値をランダムな記号にマッピングし、LLMが学習した規則を抽象的な表現に転送できるかどうかをテストしました。これにより、LLMが単に数値を記憶しているのか、それとも一般的な算術原則を理解しているのかを区別することが可能になりました。例：`7 -> y`
3.  **算術特性の検証:** LLMの加算結果が、可換性（A + B = B + A）などの基本的な算術特性を満たしているかどうかを検証しました。
4.  **明示的な規則の提供と性能への影響評価:** LLMに明示的な加算規則を提供し、その規則がLLMの性能にどのように影響するかを調査しました。これは、外部から提供された規則とLLMが内部に持っている知識との間のずれを明らかにするのに役立ちました。

## 3. 結果、何が達成できたのか

本研究により、以下の重要な発見がありました。

*   **記号表現に対する性能劣化:** LLMは、数値による加算では高い精度を示すものの（73.8-99.8%）、記号マッピングを行うと性能が著しく低下しました（≤7.5%）。これは、LLMが学習した規則を一般化できていないことを示唆しています。
*   **非単調な性能変化:** LLMの性能は、桁数が増えるにつれて単調に低下するのではなく、非単調な変化を示しました。これは、LLMが真のアルゴリズムを実行しているのではなく、桁数パターンを記憶している可能性を示唆しています。
*   **可換性の違反:** LLMは、可換性を頻繁に違反しました（A + B ≠ B + Aとなるケースが1700件以上）。これは、LLMが加算の基本的な数学的特性を理解していないことを示唆しています。
*   **明示的な規則の提供による性能低下:** LLMに明示的な加算規則を提供すると、平均で81.2%も性能が低下しました。これは、LLMの算術処理が人間が定義した原則と一致していないことを示唆しています。
*   **自己説明によるベースライン維持:** LLMに自己説明をさせた場合、ベースライン精度が維持されました。

これらの結果から、現在のLLMは、真の規則学習よりも、記憶されたパターンに依存していることが示唆されました。

## 4. Limitationや問題点は何か

本研究の限界点は以下の通りです。

*   **対象演算の限定:** 本研究では、二整数加算という基本的な演算に焦点を当てているため、結果がより複雑な数学演算や推論タスクに一般化できるかどうかは不明です。
*   **記号マッピングの限界:** 記号マッピングは、LLMの抽象化能力を評価する有効な方法ですが、現実的な数学的コンテキストでは、パターン認識が有効な問題解決戦略となる場合もあります。
*   **知識の内部化方法の限定:** 知識の内部化方法として、教師あり学習と強化学習に焦点を当てていますが、他のアプローチ（例えば、自己教師あり学習）も存在します。
*   **モデルアーキテクチャとトレーニングパラダイム:** 研究対象としたのは既存のモデルアーキテクチャとトレーニングパラダイムに限定されており、真の数学的推論を実現するための代替アプローチが存在する可能性があります。
*   **データセットの制約:** 使用したデータセットは合成データであり、現実世界の数学の問題を完全に反映しているわけではありません。

本研究では、以下の技術的な詳細が用いられています。

*   **モデル:** Llama（複数の世代）、Qwen、Gemma、DeepSeek-V3/R1、Claude-3.5-sonnet、Gemini (2.0, 2.5-pro)など、様々なモデルアーキテクチャとパラメータサイズを持つLLMを使用しました。

# FlexIP: Dynamic Control of Preservation and Personality for Customized Image Generation

[View Paper](http://arxiv.org/abs/2504.07405v1)

## 1. 既存研究では何ができなかったのか

既存の subject-driven な画像生成手法は、主に以下の点で限界がありました。

*   **identity preservation と personalized manipulation のトレードオフ:**  既存の手法は、対象の identity (同一性) を保持することと、多様な編集を可能にすることの間で、本質的なトレードオフに直面していました。identity preservation を重視すると編集の自由度が制限され、編集の自由度を高めると identity が損なわれる傾向がありました。
*   **zero-shot editing の限界:** zero-shot editing (fine-tuning なしでの編集) において、image-text modalities を align するために vision-language models (VLMs) の Q-former のような alignment modules を採用することが多かったですが、これらは画像生成タスクに必要な広範で複雑な visual knowledge を capture するには不十分でした。
*   **feature の競合:** 既存の single-path のアプローチでは、identity preservation と personalization の feature が競合し、明示的な分離が困難でした。
*   **訓練データの影響:** 静止画像ペアで訓練されたモデルは copy-paste artifact を生成しやすく、一方、ビデオフレームで訓練されたモデルは identity preservation が弱まる傾向がありました。
*   **制御性の低さ:** 既存の手法では、identity preservation と personalization のバランスを正確に制御することが難しく、急激な変化が生じることがありました。

## 2. どのようなアプローチでそれを解決しようとしたか

FlexIP は、上記の課題を解決するために、以下の主要なアプローチを採用しました。

*   **identity preservation と personalization の分離:** identity preservation と personalized editing を独立して制御可能な dimensions に分離しました。
*   **dual-adapter architecture の導入:** Personalization Adapter (stylistic manipulation 用) と Preservation Adapter (identity maintenance 用) という2つの専用 component を導入しました。
*   **dynamic weight gating mechanism の開発:** inference 時に adapter の weight を動的に調整することで、identity preservation と personalization のバランスを柔軟に制御できるようにしました。
*   **modality-aware weighting strategy の導入:** 画像データとビデオデータの両方を使用して訓練することで、それぞれの modality の強みを活用し、弱点を補完しました。画像データに対しては identity consistency を強制し、ビデオデータに対しては temporal coherence を利用して構造的に coherent な deformations を誘導しました。
*   **high-level と low-level feature の統合:** Preservation Adapter は、high-level semantic concepts と low-level spatial details の両方を capture することで、identity の詳細を保持します。

## 3. 結果、何が達成できたのか

FlexIP の導入により、以下の点が達成されました。

*   **identity preservation と personalized generation の両立:** 既存の手法におけるトレードオフを打破し、優れた identity preservation を実現しながら、より多様な personalized generation capabilities をサポートしました。
*   **柔軟な parameterized control:** dynamic weight gating により、identity preservation と personalization の間の continuous parametric control surface を実現し、ユーザーが柔軟にバランスを調整できるようになりました。
*   **state-of-the-art の性能:** 既存の最先端手法を上回る identity preservation 精度と編集の柔軟性を実現しました。
*   **zero-shot style transfer の向上:** instruction following と詳細な画像情報の抽出を強調した zero-shot style transfer タスクにおいて、他の手法を上回る性能を示しました。
*   **人間による評価の向上:** personalization に関する人間による評価において、image-text matching、object detail satisfaction、semantic understanding の各側面で優れた結果を示しました。

## 4. Limitationや問題点は何か

### 論文で言及されているもの

## 5. 技術的な詳細について

FlexIP は、Latent Diffusion Model (SD) を基盤としており、以下の主要な技術要素で構成されています。

1.  **Preservation Adapter:**

    *   **目的:** identity preservation のための identity-critical feature を抽出。
    *   **手法:**
        1.  Learnable queries (`Z^(L)`) と CLIP [CLS] embeddings (`Z^(C)`) を使用。Learnable queries は fine-grained な variation を capture し、CLIP [CLS] embeddings は global identity consistency を提供。
        2.  DINO Patch Embeddings (`Z^(D)`) を用いた cross-attention により、これらの embedding から詳細な visual information を抽出。

        ```python
        # 疑似コード: Preservation Adapter の処理
        def preservation_adapter(learnable_queries, clip_cls_embeddings, dino_embeddings):
            # Learnable queries と DINO embeddings を Resampler で統合
            resampler_L_output = Resampler(learnable_queries, dino_embeddings)

            # CLIP CLS embeddings と DINO embeddings を Resampler で統合
            resampler_C_output = Resampler(clip_cls_embeddings, dino_embeddings)

            # 統合された特徴を結合
            preservation_features = concatenate([resampler_L_output, resampler_C_output])

            return preservation_features
        ```

2.  **Personalization Adapter:**

    *   **目的:** text embeddings に visual context を与え、personalized editing を実現。
    *   **手法:**
        1.  Text embeddings (`Z^(T)`) が CLIP [CLS] embedding (`Z^(C)`) に attend するように、追加の resampling step を導入。
        2.  これにより、textual instructions が identity-aware になり、対象の appearance と consistent な edits を誘導。

        ```python
        # 疑似コード: Personalization Adapter の処理
        def personalization_adapter(text_embeddings, clip_cls_embeddings):
            # Text embeddings と CLIP CLS embeddings を Resampler で統合
            resampler_T_output = Resampler(text_embeddings, clip_cls_embeddings)

            return resampler_T_output
        ```

3.  **Dynamic Weight Gating (DWG):**

    *   **目的:** identity preservation と personalized editing のトレードオフを制御。
    *   **手法:**
        1.  image データと video データの両方を使用して訓練。
        2.  `gamma(x)` というデータ依存の gating weight を導入し、image データに対しては preservation を優先し、video データに対しては stylization を優先。

        ```python
        # 疑似コード: Dynamic Weight Gating の処理
        def dynamic_weight_gating(preservation_features, personalization_features, data_type, alpha, beta):
            if data_type == "image":
                gamma = alpha
            elif data_type == "video":
                gamma = 1 - beta
            else:
                gamma = 0.5  # デフォルト値

            # Preservation features と Personalization features を重み付けして結合
            final_features = gamma * preservation_features + (1 - gamma) * personalization_features

            return final_features
        ```

# PixelFlow: Pixel-Space Generative Models with Flow

[View Paper](http://arxiv.org/abs/2504.07963v1)

## 1. 既存研究では何ができなかったのか

既存研究の主な課題は以下の通りです。

*   **潜在空間モデル(LDM)の課題:** LDMsは、Variational Autoencoder (VAE) を事前に学習し、その潜在空間でdiffusionモデルを学習するため、VAEとdiffusionモデルを独立して学習する必要があり、全体の最適化が困難でした。また、VAEによる圧縮によって高周波の詳細が失われ、生成された画像にアーティファクトが生じる可能性がありました。
*   **ピクセル空間モデル(PDM)の課題:** ピクセル空間で直接diffusionモデルを学習する場合、高解像度画像では計算コストが非常に高くなります。そのため、多くのPDMは、低解像度画像を生成してから、アップサンプラーで高解像度化するカスケードアプローチを採用していました。しかし、このアプローチでは、各段階で個別のネットワークを学習する必要があり、エンドツーエンドの最適化が難しくなっていました。
*   **VAEに頼らないモデルの課題:** VAEを使用せずにピクセル空間で直接画像生成を行うモデルも存在しましたが、高解像度画像の生成には計算効率の問題がありました。また、diffusionモデルを用いた超解像処理は、ノイズから始める必要があり、時間効率が悪いという課題がありました。

## 2. どのようなアプローチでそれを解決しようとしたか

PixelFlowは、上記の問題を解決するために、以下の戦略を採用しました。

*   **エンドツーエンドのピクセル空間生成:** VAEを使用せず、生のピクセル空間で直接画像生成を行うことで、VAEの事前学習やアーティファクトの問題を解消しました。
*   **カスケードフローモデリング:** 低解像度から高解像度へのカスケードフローモデリングにより、計算コストを削減しました。初期段階では低解像度でノイズ除去を行い、段階的に解像度を上げることで、高解像度での計算量を抑えました。
*   **マルチスケール学習:** 異なる解像度の画像をモデルに入力し、モデルが統一されたパラメータセットでマルチスケールサンプルを処理できるようにしました。学習時には、画像をリサイズしてノイズを追加し、隣接するスケールのノイズ画像間で補間を行い、velocity predictionを行います。
*   **Flow Matching:** Flow Matchingを用いて、ノイズから画像への変換を学習します。これにより、任意の2つの分布間を補間することが可能になり、画像生成タスクにおいて、ノイズから画像への変換だけでなく、画像から画像への変換にも応用できます。

疑似コードで示すと、以下のようになります。

```python
# 学習時
def train_step(image):
  # 1. マルチスケールサンプルの作成
  scales = [resize(image, scale) for scale in [1/8, 1/4, 1/2, 1]] # 例: 4段階
  noisy_scales = [add_noise(scale) for scale in scales]

  # 2. スケール間を補完
  t = random() # 0~1のランダムな値
  interpolated_image = t * noisy_scales[-1] + (1 - t) * noisy_scales[-2] # 一番高解像度の二つで補完する例

  # 3. velocity prediction
  predicted_velocity = model(interpolated_image, t)

  # 4. loss計算 (MSE loss)
  true_velocity = noisy_scales[-1] - noisy_scales[-2]
  loss = mse_loss(predicted_velocity, true_velocity)
  return loss

# 推論時
def inference():
  # 1. 最小解像度でノイズ生成
  x = gaussian_noise(resolution=(8, 8)) # 例: 8x8

  # 2. カスケード状に解像度を上げながらノイズ除去
  for scale in [1/8, 1/4, 1/2, 1]: # 例: 4段階
    for step in range(num_steps):
      t = step / num_steps # 0~1
      velocity = model(x, t)
      x = x + velocity * step_size # Euler法的な更新
    if scale < 1:
      x = upscale(x)
  return x
```

## 4. Limitationや問題点は何か

PixelFlowの制限事項と問題点は次のとおりです。

## 5. 技術的な詳細について

PixelFlowの技術的な詳細を以下に示します。

*   **アーキテクチャ:**
    *   Transformerベースのアーキテクチャ（DiT: Diffusion Transformer）をベースにしています。
    *   入力画像をパッチに分割し、線形変換によってトークン化します(ViTの設計を踏襲)。
    *   複数の解像度のトークンをバッチ内で効率的に処理するため、シーケンスパッキング戦略を使用します。異なる長さのflattenされたトークンシーケンスを連結します。
    *   位置エンコーディングには、RoPE (Rotary Position Embedding) を採用しています。2D画像データに対しては、高さと幅の次元に独立して1D-RoPEを適用します。
    *   各Transformerブロック内のself-attention層の後に、cross-attention層を追加し、テキスト情報を統合します。
*   **学習:**
    *   Flow Matchingを用いて、ノイズから画像への変換を学習します。
    *   マルチスケールサンプルを生成するために、画像を異なる解像度にリサイズし、ノイズを追加します。
    *   解像度を区別するために、patch embedding後の特徴マップの絶対解像度を条件信号として使用します。
    *   損失関数には、MSE (Mean Squared Error) を使用します。
*   **推論:**
    *   Euler discrete samplerまたはDopri5 solverを使用して、画像を生成します。
    *   スケール間のスムーズな移行を保証するために、renoising戦略を採用しています。
    *   Classifier-Free Guidance (CFG)を用いて、生成される画像の品質とテキストの一貫性を制御します。ステージごとに異なるCFG値を適用する、段階的なCFGスケジューリングを提案しています。
*   **Flow Matchingの詳細:**

    Flow Matchingでは、以下の式で表されるように、標準正規分布からのサンプル $\mathbf{x}_0$  とターゲット分布からのサンプル $\mathbf{x}_1$ を用いて、timestep $t$  におけるサンプル $\mathbf{x}_t$ を線形補間として定義します。

    $\displaystyle\mathbf{x}_{t}=t\cdot\mathbf{x}_{1}+(1-t)\cdot\mathbf{x}_{0}$

    モデルは、常微分方程式(ODE)で定義されるvelocity $\mathbf{v}_t = \frac{d\mathbf{x}_t}{dt}$ を近似するように学習されます。

    学習時には、ターゲットサンプル $\mathbf{x}_1$ と標準正規分布からのサンプル $\mathbf{x}_0$ をサンプルし、timestep $t$ を選択します。その後、線形補間によってサンプル $\mathbf{x}_t$ を生成し、モデルに $\mathbf{x}_t$ と $t$ を入力してvelocity $\mathbf{v}_t$ を予測させます。モデルの予測値と実際のvelocityとの間のMSE損失を最小化するように学習を進めます。

    推論時には、標準正規分布からサンプル $\mathbf{x}_0$ を生成し、timestep $t$ を徐々に変化させながら、モデルによって予測されるvelocityを用いて $\mathbf{x}_t$ を更新していきます。

# SQL-R1: Training Natural Language to SQL Reasoning Model By Reinforcement Learning

[View Paper](http://arxiv.org/abs/2504.08600v1)

## 1. 既存研究では何ができなかったのか

既存のNatural Language to SQL (NL2SQL) モデルは、以下の点で課題が残っていました。

*   **複雑なシナリオにおける推論性能の限界:** 特に、複数のテーブル結合やネストされたクエリを含む複雑なデータベースシナリオにおいて、十分な推論性能を発揮できていませんでした。
*   **ドメイン適応性と汎化性の課題:** Supervised Fine-Tuning (SFT) を主な学習方法としていたため、新しいデータベース環境（例：金融、医療）への適応や汎化が難しいという問題がありました。SFT はデータベーススキーマの構造やトレーニングデータの規模に依存するため、既存モデルの安定性が損なわれる可能性がありました。
*   **推論ロジックの解釈可能性の欠如:** NL2SQL の推論ロジックの解釈可能性が低いため、金融や医療といったリスクの高い分野への応用が制限されていました。
*   **複雑なクエリに対するSQL生成の困難さ:**複雑なデータベーススキーマやあいまいなセマンティクスの場合、ファインチューニングされたモデルは、固定された生成戦略と過去のデータに依存するため、ユーザーの意図に沿わないSQLを生成する可能性がありました。

## 2. どのようなアプローチでそれを解決しようとしたか

SQL-R1 では、上記の課題を解決するために、以下の新しいアプローチを導入しました。

*   **強化学習 (RL) による NL2SQL モデルのトレーニング:** Supervised Fine-Tuning (SFT) の代わりに、強化学習アルゴリズムを用いて NL2SQL モデルをトレーニングしました。これにより、モデルがデータベースとのインタラクションを通じて動的に学習し、より複雑な推論タスクに対応できるようにしました。
*   **NL2SQL タスクに特化した RL ベースの報酬関数の設計:** NL2SQL タスクに特化した報酬関数を設計し、モデルがユーザーのクエリ意図を正確に反映した SQL クエリを生成するように促しました。Format Reward、Execution Reward、Result Reward、Length Rewardという４つの報酬によって、SQLの品質を高めるようにしました。
*   **コールドスタート戦略の導入:** ベースモデルに対して、特定のデータを用いた SFT によるコールドスタートを行うことで、モデルの指示追従能力と NL2SQL 生成能力を強化しました。
*   **データエンジニアリングによるデータ拡張:** 既存のデータエンジニアリング技術を活用して、モデルのトレーニングをサポートするための合成 NL2SQL データを生成し、モデルのロバスト性と汎化性を向上させました。
*   **Group Relative Policy Optimization (GRPO) アルゴリズムの利用:** GRPOアルゴリズムを導入することで、Value Modelの不要、メモリ要件の低減、報酬ターゲットの明確化を実現し、NL2SQLのポリシーモデルを効率的に最適化。
*   **推論時に自己整合性投票を導入:** 推論時に複数のSQL候補を生成し、最も高いスコアのSQLを最終的な回答として選択。これにより、SQL生成の精度を向上。

## 3. 結果、何が達成できたのか

SQL-R1 は、以下の点で優れた成果を達成しました。

*   **高い実行精度:** ベンチマークデータセット Spider および BIRD において、それぞれ 88.6% および 66.6% の実行精度を達成しました。これは、7B のベースモデルのみを使用した場合の結果であり、既存のクローズドソース LLM (GPT-4, GPT-4oなど) を使用した NL2SQL ソリューションと比較して遜色ない、あるいはそれ以上の性能です。

## 2. どのようなアプローチでそれを解決しようとしたか

Pangu Ultraでは、トレーニングの安定性を高めるために、depth-scaled sandwich normalizationを導入しました。これは、モデルの深さ方向にスケーリングされたnormalization手法であり、深いモデルのトレーニングプロセス中にloss spikesを効果的に抑制することを目的としています。具体的には、従来のnormalization層に加えて、層の入力と出力に対して追加のnormalizationを適用し、勾配の爆発や消失を防ぎます。

疑似コードで示すと、以下のようになります。

```python
def depth_scaled_sandwich_normalization(x, gamma, beta, epsilon=1e-5):
  """
  Depth-scaled sandwich normalizationの実装 (簡略化)

  Args:
    x: 入力テンソル
    gamma: スケールパラメータ
    beta: シフトパラメータ
    epsilon: 数値安定性のための小さい値

  Returns:
    正規化されたテンソル
  """
  # 入力に対するNormalization
  mean = np.mean(x, axis=-1, keepdims=True)
  variance = np.var(x, axis=-1, keepdims=True)
  x_normalized_input = (x - mean) / np.sqrt(variance + epsilon)
  x_normalized_input = x_normalized_input * gamma + beta

  # レイヤーの処理 (例: 線形変換)
  y = linear_transformation(x_normalized_input)  # 仮の関数

  # 出力に対するNormalization
  mean_output = np.mean(y, axis=-1, keepdims=True)
  variance_output = np.var(y, axis=-1, keepdims=True)
  y_normalized_output = (y - mean_output) / np.sqrt(variance_output + epsilon)
  y_normalized_output = y_normalized_output * gamma + beta

  return y_normalized_output
```

# SAEs $\textit{Can}$ Improve Unlearning: Dynamic Sparse Autoencoder Guardrails for Precision Unlearning in LLMs

[View Paper](http://arxiv.org/abs/2504.08192v1)

## 1. 既存研究では何ができなかったのか

既存のLLMの機械学習忘却に関する研究は、主に以下の点で課題を抱えていました。

*   **計算コストが高い:** 勾配に基づく忘却手法は、LLMのパラメータを更新するために膨大な計算リソースを必要とし、実用的な忘却が困難でした。
*   **ハイパーパラメータの不安定性:** 勾配に基づく手法は、ハイパーパラメータの設定に非常に敏感であり、わずかな調整で忘却性能やモデルの有用性が大きく変動する可能性がありました。
*   **逐次的な忘却が苦手:** 複数の忘却要求が連続して発生する場合、既存手法ではモデルの性能が急速に劣化する「壊滅的忘却」が発生しやすくなっていました。
*   **再学習攻撃に脆弱:** 忘却されたはずの知識が、敵対的な再学習（relearning）によって比較的容易に回復されてしまう問題がありました。
*   **データ効率が低い:** 忘却対象データが多く必要な場合や、そもそもデータが全くないゼロショット設定では有効な忘却が困難でした。
*   **解釈可能性が低い:** 既存の忘却手法は、モデルがどのように知識を忘却したのかを理解することが難しく、安全性や信頼性の検証が困難でした。
*   **従来のSAEに基づくアプローチの限界:** スパースオートエンコーダ（SAE）を用いた忘却手法は、ターゲットを絞った介入による忘却の可能性を示すものの、既存のアプローチでは、精度が低く、意図しない副作用を引き起こすため、勾配ベースの手法を下回る結果となっていました。

## 2. どのようなアプローチでそれを解決しようとしたか

この論文では、上記の課題を解決するために、Dynamic SAE Guardrails (DSG)という新しい手法を提案しました。DSGは、以下の主要な要素で構成されています。

1.  **因果関係に基づく特徴選択:** Fisher情報に基づいて、忘却対象の知識と因果関係が強いSAEの特徴量を特定します。これにより、忘却に関係のない特徴量への介入を避け、モデルの有用性を維持します。疑似コードは以下のようになります。

    ```python
    def calculate_importance_ratio(feature_activations_forget, feature_activations_retain):
      forget_score = average(feature_activations_forget**2)
      retain_score = average(feature_activations_retain**2)
      importance_ratio = forget_score / max(retain_score, epsilon) # epsilonはゼロ除算を防ぐための小さな値
      return importance_ratio
    ```

2.  **動的な分類器:** 入力シーケンスが忘却対象の知識に関連するかどうかを動的に判定する分類器を導入します。この分類器は、SAEの特徴量の活性化パターンに基づいて、入力シーケンスの忘却関連度を評価し、忘却が必要な場合にのみ介入を行います。

    ```python
    def classify_input(input_sequence, selected_features, threshold):
      # input_sequenceに対する、selected_featuresのactivationを計算
      activations = calculate_feature_activations(input_sequence, selected_features)
      # activationに基づき忘却の必要性を判定
      relevance_score = sum(activations > 0) / len(input_sequence)
      if relevance_score > threshold:
        return True # 忘却が必要
      else:
        return False # 忘却は不要
    ```

3.  **ターゲットを絞ったクランピング:** 動的な分類器によって忘却が必要と判定された場合にのみ、特定されたSAEの特徴量の活性化をクランプします。これにより、モデルが忘却対象の知識にアクセスするのを防ぎつつ、一般的な能力は維持します。

    ```python
    def intervene(input_sequence, selected_features, classifier, clamp_value):
      if classifier.classify_input(input_sequence):
        # 忘却関連featureのactivationをclamp_valueに置き換え
        clamped_activations = clamp_feature_activations(input_sequence, selected_features, clamp_value)
        return clamped_activations
      else:
        return input_sequence # 何も変更しない
    ```

DSGは、これらの要素を組み合わせることで、計算効率、安定性、逐次的な忘却能力、再学習攻撃への耐性、データ効率、解釈可能性を向上させ、忘却と有用性のバランスを改善することを目指しました。

## 3. 結果、何が達成できたのか

実験の結果、DSGは以下の点で既存手法を大幅に上回る性能を達成しました。

*   **忘却性能と有用性のトレードオフの改善:** WMDPベンチマークにおいて、既存の最良手法であるRMUと比較して、より高い忘却性能を維持しながら、モデルの一般的な能力（MMLUスコア）を高く維持しました。
*   **計算効率と安定性の向上:** 勾配に基づく手法と比較して、順伝播のみで動作するため、計算コストが大幅に低減され、ハイパーパラメータの変動に対する安定性が向上しました。
*   **逐次的な忘却におけるロバスト性:** MUSEベンチマークにおいて、逐次的な忘却要求が繰り返される状況でも、モデルの性能劣化を抑制し、安定した忘却性能を維持しました。
*   **再学習攻撃に対する耐性の向上:** APIベースの脅威モデルにおいて、再学習攻撃に対する耐性が向上しました。これは、DSGがモデルの重みではなく、活性化パターンに介入するためと考えられます。
*   **データ効率の向上:** 忘却および保持データが限られた状況でも、一貫した性能を維持しました。また、ゼロショット設定においても、効果的な忘却を実現する可能性を示しました。
*   **解釈可能性の向上:** SAEの特徴量を選択的かつ動的に操作することで、モデルがどのように知識を忘却したのかを理解することが容易になりました。

## 4. Limitationや問題点は何か

DSGは多くの利点を持つ一方で、いくつかのLimitationsと問題点が存在します。

*   **完全な忘却の保証はない:** DSGは近似的な忘却手法であり、ターゲットとした知識の完全な除去を保証するものではありません。わずかな痕跡や間接的な影響が残る可能性があります。
*   **倫理的な懸念:** 忘却技術は、有害な知識の除去に役立つ一方で、検閲や意見の抑圧に悪用される可能性もあります。
*   **SAEの解釈可能性の限界:** SAEの特徴量の解釈は必ずしも明確ではなく、誤った解釈が意図しない結果を招く可能性があります。
*   **計算コスト:** SAEの学習には計算リソースが必要であり、特に大規模モデルでは無視できないコストとなります。ただし、論文中では、公開されているSAEを使用することでコストを相殺できると考察されています。
*   **推論時の遅延:** SAEを用いた介入は、元のLLMと比較して推論速度に若干の遅延をもたらします。実験結果では、DSGによる遅延増加は約5%程度と報告されています。
*   **敵対的な攻撃への潜在的な脆弱性:** 他のAI安全性研究と同様に、DSGで開発された技術が悪意のある攻撃や安全対策への抵抗を目的としたモデルの開発に悪用される可能性があります。
*   **評価の課題:** モデルから知識が完全に削除されたかどうかを評価することは困難であり、より堅牢な評価方法が必要です。

私が考える問題点としては、以下のような点が挙げられます。

*   **SAEの品質への依存:** DSGの性能は、使用するSAEの品質に大きく依存します。不適切なSAEを使用すると、忘却性能が低下したり、モデルの有用性が損なわれる可能性があります。
*   **特徴量選択のバイアス:** Fisher情報に基づく特徴量選択は、データセットのバイアスやモデルの学習バイアスに影響を受ける可能性があります。これにより、忘却対象の知識を完全にカバーできない可能性があります。
*   **動的な分類器の誤判定:** 動的な分類器は、誤って忘却が必要ないと判定したり、逆に不要な介入を行ったりする可能性があります。これにより、忘却性能が低下したり、モデルの有用性が損なわれる可能性があります。
*   **現実世界への適用可能性:** 実験は特定のベンチマークデータセットで行われており、現実世界における複雑な知識の忘却にDSGがどの程度適用可能かは不明です。

## 5. 技術的な詳細について

DSGは、以下のステップで動作します。

1.  **SAEの学習:** 大規模なテキストコーパスを用いて、LLMの特定レイヤーの活性化を再構成するようにSAEを学習させます。SAEは、エンコーダとデコーダから構成され、活性化をスパースな特徴量の組み合わせとして表現します。
2.  **特徴量選択:**
    1.  忘却データセットと保持データセットにおけるSAEの各特徴量の活性化パターンを分析します。具体的には、各特徴量について、データセット内のトークンに対する平均二乗活性化を計算します。
    2.  各特徴量の重要度比率 (importance ratio) を計算します。これは、忘却データセットにおける平均二乗活性化を、保持データセットにおける平均二乗活性化で割ったものです。
    3.  重要度比率が高い特徴量を、忘却対象の知識と関連する特徴量として選択します。具体的には、重要度比率の上位p%の特徴量を選択します。
3.  **動的な分類器の学習:**
    1.  保持データセットを用いて、入力シーケンスの忘却関連度を評価する動的な分類器を学習します。
    2.  分類器は、入力シーケンス内の選択された特徴量の活性化パターンに基づいて、シーケンスの忘却関連度スコアを計算します。具体的には、シーケンス内の特徴量が活性化されたトークンの割合を計算します。
    3.  分類器の閾値を、保持データセットにおける忘却関連度スコアの分布に基づいて決定します。具体的には、保持データセットにおける偽陽性率が一定の値以下になるように閾値を設定します。
4.  **推論時の介入:**
    1.  入力シーケンスを受け取ると、LLMは通常通り処理を行い、指定されたレイヤーの活性化を生成します。
    2.  SAEを用いて活性化を再構成し、選択された特徴量の活性化値を取得します。
    3.  動的な分類器を用いて、入力シーケンスが忘却対象の知識に関連するかどうかを判定します。
    4.  関連すると判定された場合、選択された特徴量の活性化値をクランプします。具体的には、活性化値を固定の負の値に設定します。
    5.  クランプされた活性化値を用いて、LLMは残りの処理を行い、最終的な出力を生成します。

技術的なポイントとして、SAEのアーキテクチャ、学習アルゴリズム、およびクランプ値の選択が、DSGの性能に大きく影響します。また、動的な分類器の設計と閾値の決定も、忘却性能と有用性のバランスを調整する上で重要です。

# UKBOB: One Billion MRI Labeled Masks for Generalizable 3D Medical Image Segmentation

[View Paper](http://arxiv.org/abs/2504.06908v1)

## 1. 既存研究では何ができなかったのか

既存の研究は、医療画像における大規模なラベル付きデータセットの不足という課題に直面していました。具体的には、以下の点が問題でした。

*   **データセットの規模と多様性の不足:** ImageNetのような大規模データセットの成功例がある一方で、医療画像領域ではプライバシー規制、複雑なロジスティクス、専門家によるアノテーションの高コストにより、大規模なラベル付きデータセットの作成が困難でした。既存の医療画像データセットは、規模が小さすぎるか、多様性に欠けるため、汎用的なモデルの訓練には不十分でした。胸部X線画像のような大規模なデータセットは存在するものの、詳細なセグメンテーションマスクがないため、高度な解剖学的分析には不向きでした。
*   **自動ラベリングにおけるノイズの問題:** TotalVibe Segmentatorのような自動ラベリングツールを利用しても、大規模なデータセットではラベルのノイズが避けられません。既存研究では、このようなノイズを効果的に処理し、高品質なラベルを保証するメカニズムが不足していました。特に、患者の異常とラベリングの誤りを区別することが困難でした。
*   **ドメインシフトへの対応:** U-Netなどのネットワークは教師あり学習において優れた性能を発揮しますが、テストデータが訓練データと異なる場合（プロトコルの違い、スキャナの違い、モダリティの違いなど）には性能が低下します。既存のTest-Time Adaptation（TTA）手法は、モデルが十分に調整されていることを前提としており、ノイズの多いラベルで訓練されたモデルには適していませんでした。

## 2. どのようなアプローチでそれを解決しようとしたか

この論文では、上記の課題を解決するために、以下の3つの主要なアプローチを採用しました。

1.  **大規模ラベル付きデータセットの構築 (UKBOB):**
    *   UK Biobank MRIデータセットを基に、51,761の3D MRIスキャンと13.7億を超える2Dセグメンテーションマスクを含む、大規模なラベル付きデータセットUKBOBを構築しました。
    *   TotalVibe Segmentatorを用いて自動ラベリングを行い、72の臓器に対するセグメンテーションマスクを生成しました。

2.  **ラベルの品質管理:**
    *   統計的な Specialized Organ Labels Filter（SOLF）を提案し、臓器の形状、体積に基づいてラベルをフィルタリングしました。SOLFは、臓器の体積、球形度、偏心率の3つの特徴量を使用し、異常な特徴を持つラベルを排除します。
    ```python
    def solf_filter(organ_volume, body_volume, sphericity, eccentricity, epsilon=0.05):
      # epsilon: 許容範囲の割合 (例: 0.05 は 5%)
      normalized_volume = organ_volume / body_volume
      volume_min = percentile(all_normalized_volumes, epsilon / 2 * 100)
      volume_max = percentile(all_normalized_volumes, (1 - epsilon / 2) * 100)

      sphericity_min = percentile(all_sphericity, epsilon / 2 * 100)
      sphericity_max = percentile(all_sphericity, (1 - epsilon / 2) * 100)

      eccentricity_min = percentile(all_eccentricity, epsilon / 2 * 100)
      eccentricity_max = percentile(all_eccentricity, (1 - epsilon / 2) * 100)

      # 各特徴量が許容範囲内にあるか判定
      volume_in_range = volume_min <= normalized_volume <= volume_max
      sphericity_in_range = sphericity_min <= sphericity <= sphericity_max
      eccentricity_in_range = eccentricity_min <= eccentricity <= eccentricity_max

      # 少なくとも2つの特徴量が範囲外の場合、フィルタリング
      if sum([volume_in_range, sphericity_in_range, eccentricity_in_range]) >= 1:
          return True # フィルタリング対象
      else:
          return False # フィルタリング対象外
    ```
    *   300のMRIに対して手動でラベル付けを行い（UKBOB-manual）、自動ラベリングの検証データとして使用しました。

3.  **ノイズのあるラベルに対するロバスト性の向上:**
    *   Entropy Test-Time Adaptation（ETTA）を提案し、テスト時にモデルの予測エントロピーを最小化するようにバッチ正規化パラメータを微調整しました。これにより、ドメインシフトやラベルノイズに対するロバスト性を向上させました。

## 3. 結果、何が達成できたのか

この研究の結果として、以下の点が達成されました。

*   **大規模高品質なデータセットの構築:** UKBOBは、既存の医療画像セグメンテーションデータセットと比較して、規模と多様性において圧倒的な優位性を示しました。
*   **ラベル品質の検証:** SOLFフィルタリングと手動アノテーションによる検証により、UKBOBのラベルの品質が高いことが確認されました。手動アノテーションとのDiceスコアは0.873、既存の手動脊椎ラベルとのDiceスコアは0.811でした。SOLFを用いることで、Dice scoreが0.018-0.056向上しました。
*   **汎用的な基礎モデルの訓練:** UKBOBを用いて訓練されたSwin-BOBは、BRATS脳腫瘍MRIチャレンジで0.4%の改善、BTCV腹部CTスキャンベンチマークで1.3%の改善など、3D医療画像における複数のベンチマークで最先端の結果を達成しました。
*   **ゼロショット汎化性能の検証:** UKBOBで訓練されたモデルが、AMOS腹部MRIデータセットなどの類似ドメインのデータセットに対して、ゼロショットで優れた汎化性能を示すことが確認されました。
*   **ETTAによる性能向上:** ETTAを適用することで、様々なネットワークとタスクにおいて一貫して性能が向上することが示されました。特に、ノイズの多いラベルで訓練されたモデル（Swin-BOB）において、ETTAの有効性が確認されました。

## 4. Limitationや問題点は何か。本文で言及されているものの他、あなたが考えるものも含めて

論文で言及されている制限事項と問題点は以下の通りです。

*   **MRIスキャン範囲の制限:** UKBOBは首から膝までのMRIスキャンに限定されており、他のモダリティや解剖学的領域をカバーしていません。
*   **残存するラベルノイズ:** 自動ラベリングとフィルタリングを行っても、ラベルノイズが完全に排除されているわけではありません。

私が考える追加の制限事項と問題点は以下の通りです。

*   **データセットの偏り:** UK Biobankの参加者は特定の人口統計学的属性を持つ可能性があり、データセットが全体的な人口を代表していない可能性があります。これにより、モデルの汎化性能に影響を与える可能性があります。
*   **SOLFのパラメータ調整:** SOLFの性能は、球形度、偏心率、正規化体積の閾値に依存します。これらのパラメータは経験的に設定されている可能性があり、異なるデータセットやタスクに最適化されているとは限りません。
*   **ETTAの計算コスト:** ETTAはテスト時にモデルを微調整するため、計算コストが増加する可能性があります。リアルタイムアプリケーションなど、計算リソースが限られている環境では、ETTAの適用が難しい場合があります。
*   **ラベルの不均衡:** 72の臓器のラベル分布が不均衡である可能性があります。ラベル数の少ない臓器に対するセグメンテーション性能が低い可能性があります。
*   **評価指標の限界:** Dice係数とHausdorff距離は一般的な評価指標ですが、セグメンテーションの品質を完全に反映しているわけではありません。特に、臨床的な観点からの妥当性を評価するには、専門家による評価が必要となる場合があります。

*   **データセット構築:**
    *   UK Biobankの51,761件のMRIスキャンデータを使用。各スキャンは、脂肪のみ、水のみ、インフェーズ、アウトフェーズの4つのシーケンスを含む。

*   **訓練の詳細:**
    *   データセットを80%（訓練）、10%（検証）、10%（テスト）に分割。
    *   入力は96x96x96ボクセルにクロップ。

    *   損失関数として、Binary Cross-EntropyとDice Similarity Coefficient（DSC）を使用。
    *   検証セットで最高のDiceスコアを達成したモデルを保存。

*   **推論の詳細:**
    *   ETTAを適用し、テストサンプルごとにバッチ正規化パラメータを微調整。エントロピー損失を最小化するようにパラメータを更新。
    ```python
    def entropy_test_time_adaptation(model, test_dataloader, optimizer, num_epochs):
      model.train() # バッチ正規化を更新するために train mode に設定

      for epoch in range(num_epochs):
          for x, _ in test_dataloader: # ラベルは不要なので _ で受け取る
              optimizer.zero_grad()
              y_pred = model(x)
              entropy_loss = calculate_entropy_loss(y_pred) # entropy loss の計算
              entropy_loss.backward() # 勾配計算
              optimizer.step() # バッチ正規化パラメータの更新

      model.eval() # 評価モードに戻す
      return model

    def calculate_entropy_loss(predictions):
      # predictions: モデルの出力 (確率)
      epsilon = 1e-8 # log(0) を避けるための微小値
      entropy = -torch.mean(predictions * torch.log(predictions + epsilon))
      return entropy
    ```

# InteractVLM: 3D Interaction Reasoning from 2D Foundational Models

[View Paper](http://arxiv.org/abs/2504.05303v1)

## 1. 既存研究では何ができなかったのか

既存研究では、主に以下の点が困難でした。

*   **in-the-wild画像からの正確な3D人間とオブジェクトの接触点推定:** 既存の手法は、遮蔽、奥行きの曖昧さ、オブジェクト形状の多様性により、単一の自然画像から3D接触点を推定するのが困難でした。
*   **3D接触アノテーションの不足:** 既存の手法は、高価なモーションキャプチャシステムや手間のかかる手動ラベリングによって収集された3D接触アノテーションに依存しており、スケーラビリティと汎化性能が制限されていました。特に、人間とオブジェクトのペアになった3D接触ラベル付きのin-the-wild画像データセットが不足していました。オブジェクトの接触に関するデータセットも不足していました。
*   **複雑なインタラクションのモデリング:** 既存の手法は、接触予測を単純な二値分類として扱い、身体部位が「任意の」オブジェクトと接触しているかどうかを検出するだけでした。複数のオブジェクトとの同時接触など、複雑な意味的関係を捉えられていませんでした（例：椅子に座りながらラップトップを使用するなど）。
*   **3Dの推論:** 大規模ビジョン言語モデル（VLM）は2Dでしか推論できないため、人間とオブジェクトの接触という本質的に3Dの問題を解決するのが困難でした。

## 2. どのようなアプローチでそれを解決しようとしたか

InteractVLMは、以下の要素を組み合わせることで、上記の問題を解決しようとしました。

*   **Vision-Language Models (VLMs)の活用:** 大規模なVLMの広範な視覚知識を利用し、限られた3D接触データでファインチューニングすることで、データ不足を克服しました。
*   **Render-Localize-Lift (RLL)モジュールの導入:** 3D問題を2Dに変換するために、新しいRLLモジュールを導入しました。
    1.  **Render:** 3Dの身体とオブジェクトの表面をマルチビューレンダリングによって2D空間に埋め込みます。具体的には、人間のボディメッシュとオブジェクトの3Dメッシュを複数の視点から2D画像としてレンダリングします。オブジェクトについては、大規模な3Dデータベースから3Dメッシュを効率的に検索します。
    2.  **Localize:** 新しいマルチビューローカリゼーションモデル（MV-Loc）をトレーニングして、2Dで接触を推論します。
    3.  **Lift:** 推論された2D接触を3Dにリフトします。具体的には、予測された2D接触点をバックプロジェクションによって3D点に変換します。
*   **Semantic Human Contact推定タスクの提案:** オブジェクトのセマンティクスに基づいて人間の接触予測を条件付けする、新しい「Semantic Human Contact」推定タスクを提案し、より豊富なインタラクションモデリングを可能にしました。
*   **マルチビュー一貫性の考慮:** 既存手法が各ビューを独立して扱うことによる問題を解決するため、マルチビューレンダリングにカメラパラメータを単純に追加するだけでなく、Multi-view Localizationモデルを構築し、各ビューで推論された2D接触を3Dにリフトして3D損失を計算することで、マルチビューの一貫性を確保しました。
*   **最適化ベースの手法による3D再構成:** 推論された接触を制約として使用して、オブジェクトメッシュを画像にフィットさせる最適化ベースの方法を開発しました。

## 3. 結果、何が達成できたのか

InteractVLMは、以下の点で既存研究を上回る成果を達成しました。

*   **接触点推定の精度向上:** 接触点推定において、既存手法を大幅に上回る性能を示しました。
*   **3D再構成の実現:** 自然画像からの3D再構成を可能にしました。具体的には、人間の身体とオブジェクトの3Dポーズを推定し、それらの接触を推論し、最後にそれらを利用してメッシュを画像のエビデンスにフィットさせました。
*   **多様なオブジェクトカテゴリへの対応:** ペアの人間-オブジェクト接触トレーニングデータを必要としないため、従来の研究よりも多くのカテゴリでトレーニングできます。
*   **Semantic Human Contact推定タスクの実現:** 身体接触をオブジェクトラベルに基づいて推論する新しいタスクを導入し、よりリッチな相互作用のモデリングを可能にしました。
*   **限定的な3Dアノテーションデータでの高性能:** 大規模なVLMを活用することで、高価な3D接触アノテーションへの依存を軽減し、限定的なデータでも高性能を達成しました。5%のデータで、全データセットで学習した既存手法と同等の性能を発揮しました。

## 4. Limitationや問題点は何か

InteractVLMには、以下の制限事項と問題点があります。

*   **異常なポーズへの対応:** 人間の接触予測において、一般的ではないまたは曖昧なポーズに対しては、性能が低下する場合があります。例えば、人がベッドで珍しい姿勢で寝ている場合などです。
*   **オブジェクトの接触に関するデータセットの不足:** オブジェクトの接触に関するin-the-wild画像データセットが存在しないため、アフォーダンスデータで学習していますが、実際には接触点ではなく、接触の可能性を推定しているという問題があります。特に椅子のような大きなオブジェクトでは、接触とアフォーダンスの区別が曖昧になることがあります。
*   **オブジェクト検索の失敗:** 遮蔽が多い、または視覚的に曖昧なシナリオでは、オブジェクト検索が失敗する可能性があります。
*   **オブジェクトデータベースの制約:** オブジェクト検索は、基礎となるオブジェクトデータベースの豊富さと多様性に制限されます。

**その他に考えられる問題点:**

*   **計算コスト:** 大規模なVLMを使用するため、推論に高い計算コストがかかる可能性があります。
*   **一般的な3D再構成の課題:** 奥行きの曖昧さや遮蔽など、3D再構成固有の課題が残ります。
*   **ドメインギャップ:** VLMが学習したデータと、特定のタスクのデータとの間にドメインギャップが存在する可能性があります。

## 5. 技術的な詳細について

InteractVLMの技術的な詳細は以下の通りです。

*   **アーキテクチャ:**
    *   **Vision Language Model (VLM):** 事前学習済みのVLM (例: BLIP-2, Kosmos-2) を利用します。VLMは、画像エンコーダと言語モデルで構成され、画像とテキスト間のクロスアテンションメカニズムを使用します。
    *   **Render-Localize-Lift (RLL)モジュール:**
        *   **Render:** 3Dの人体メッシュとオブジェクトの点群を複数の視点から2D画像としてレンダリングします。人体メッシュはSMPLモデルのようなパラメータ化されたモデルを使用し、オブジェクトは3Dデータベースから検索したメッシュを使用します。
        *   **Multi-view Localization (MV-Loc):** レンダーされたマルチビュー画像を処理し、各視点から2D接触マップを予測します。MV-Locは、畳み込みニューラルネットワーク (CNN) を使用して、ビュー間の空間的整合性を考慮した特徴抽出を行います。マルチビューの一貫性を保つため、各ビューで推論された2D接触を3Dにリフトし、3D損失を計算します。具体的には、2Dの接触予測を3D空間にバックプロジェクションし、3Dの接触に関する損失関数を最小化するように学習します。
        *   **Lift:** 予測された2D接触点をバックプロジェクションによって3D点に変換します。既知の3Dジオメトリ（人体メッシュとオブジェクト点群）との交点を計算し、接触点を絞り込みます。
*   **損失関数:**
    *   **Token Prediction Loss:** VLMの出力を特定のトークン (例: `<human>`, `<object>`) に関連付け、クロスエントロピー損失を最小化します。
        ```python
        def token_prediction_loss(T_gt, T_pred):
            loss = -sum(T_gt[i] * log(T_pred[i]) for i in range(len(T_gt)))
            return loss
        ```

        ```python
        def focal_weighted_bce_loss(p_M_pred, p_M_gt, alpha, gamma):
            loss = -alpha * (1 - p_M_pred)**gamma * log(p_M_pred) - (1 - alpha) * p_M_pred**gamma * log(1 - p_M_pred)
            return loss

        def dice_loss(M_pred, M_gt, epsilon):
            numerator = 2 * sum(M_pred[i] * M_gt[i] for i in range(len(M_pred))) + epsilon
            denominator = sum(M_pred) + sum(M_gt) + epsilon

            return loss
        ```

        ```python
        def contact_loss_human(p_hc_pred, C_gt, alpha, gamma, lambda_val):
            loss = alpha * (1 - p_hc_pred)**gamma * log(p_hc_pred) + lambda_val * sum(abs(C_gt))
            return loss

        def dice_loss(C_O_pred, C_O_gt, epsilon):
            numerator = 2 * sum(C_O_pred[i] * C_O_gt[i] for i in range(len(C_O_pred))) + epsilon
            denominator = sum(C_O_pred) + sum(C_O_gt) + epsilon

             return loss
        ```

# GigaTok: Scaling Visual Tokenizers to 3 Billion Parameters for Autoregressive Image Generation

[View Paper](http://arxiv.org/abs/2504.08736v1)

## 1. 既存研究では何ができなかったのか

既存研究では、visual tokenizerを単純にスケールアップすると、画像の再構成品質は向上するものの、下流のautoregressive (AR) モデルによる生成品質が低下するという問題がありました。これは、既存の研究では十分に解決されていませんでした。つまり、tokenizerの規模を大きくすると、より詳細な情報を捉えられるようになる一方で、ARモデルが学習すべき潜在空間が複雑になりすぎて、結果として生成性能が劣化するというトレードオフが生じていたのです。 また、tokenizerモデルの規模拡大の効果、特に下流モデルへの影響については、既存研究で詳細な分析が行われていませんでした。

## 2. どのようなアプローチでそれを解決しようとしたか

GigaTokでは、以下の3つの主要なアプローチでこの問題に対処しました。

1.  **Semantic Regularizationの導入:** tokenizerのdecoderの中間特徴量と、事前に学習されたvisual encoder (DINOv2) から抽出された意味的に一貫性のある特徴量を揃えるsemantic regularizationを提案しました。これにより、tokenizerが過度に複雑な潜在空間を学習するのを防ぎ、下流のARモデルがより効果的に学習できるように潜在空間の複雑さを抑制しました。疑似コードで表現すると以下のようになります。

```python
# tokenizer decoder の中間層の特徴量
tokenizer_features = tokenizer.decoder.intermediate_features(image)

# 事前学習済みDINOv2モデルの特徴量
dino_features = dino_model(image)

# semantic regularization loss：tokenizerの特徴量とDINOの特徴量の類似度を最大化
regularization_loss = similarity(tokenizer_features, dino_features)

# 全損失：VQGAN損失とsemantic regularization lossの重み付き和
total_loss = vqgan_loss + lambda * regularization_loss
```

2.  **Tokenizerのスケーリングに関する実践:**

    *   **1D tokenizerの使用:** 2D tokenizerと比較して、より高いスケーラビリティを示す1D tokenizerを使用しました。具体的には、CNNとTransformerを組み合わせたハイブリッドアーキテクチャを採用し、TransformerモジュールにはQ-Formerを使用しました。
    *   **Decoderのスケーリングの優先:** encoderとdecoderの両方を拡大する際に、decoderのスケーリングを優先することで、より効率的なパラメータ割り当てを実現しました。
    *   **Entropy Lossの採用:** tokenizerを数十億パラメータ規模にスケーリングする際の学習の安定化のために、entropy lossを採用しました。 entropy loss は、コードブックの使用率を高め、学習の安定化に貢献します。

```python
# コードブックの使用率を均一にするためのエントロピー損失
entropy_loss = expected_entropy_given_input - entropy_of_expected_output
```

3.  **AR Probingによる評価:** tokenizerの訓練プロセスを監視するために、軽量な下流生成ARモデルを訓練するAR probingスキームを提案しました。これにより、大規模なARモデルを十分に訓練するよりも効率的に、tokenizerが下流の生成に与える影響を評価できるようになりました。

## 3. 結果、何が達成できたのか

GigaTokによって、以下の成果を達成しました。

*   **Reconstruction vs. Generationのジレンマの解消:** semantic regularizationによって、tokenizerのスケーリングにおけるreconstruction品質の向上とgeneration品質の低下というトレードオフを解消し、両方の性能を同時に向上させることに成功しました。
*   **大規模Tokenizerの実現:** 30億パラメータにスケールされたGigaTokは、画像の再構成、下流のAR生成、および下流のAR表現品質において、state-of-the-artの性能を達成しました。
*   **学習効率の向上:** AR probingの導入により、tokenizerの評価に必要な計算コストを大幅に削減しました。
*   **多様なデータセットでの性能向上:** ImageNet 256のようなデータセットで、既存のモデルを上回る性能を達成しました。

## 4. Limitationや問題点は何か。本文で言及されているものの他、あなたが考えるものも含めて

論文で言及されている制限事項は以下の通りです。

*   **クラス条件付き画像生成への焦点:** 主にクラス条件付き画像生成に焦点を当てており、テキスト条件付き画像生成やビデオ生成への拡張は今後の課題として残っています。
*   **1D Tokenizerの解像度への対応:** CNNベースの2D tokenizerとは異なり、1D Transformerベースのtokenizerは、追加の訓練調整なしに複数の解像度に直接適用することはできません。
*   **データセット規模の影響:** tokenizerのモデルサイズのスケーリングに加えて、訓練データ、コードブック次元、およびコードブックサイズの変更が下流のautoregressive生成に与える影響については、今後の研究課題として残っています。
*   **tokenizerの訓練期間:** tokenizerの訓練期間が長くなると、再構成品質は向上するものの、下流の生成品質が低下する可能性があるという問題も指摘されています。データセット規模を大きくすることでこの問題を軽減できる可能性があると示唆されています。
*   **Discriminatorのスケールと強化の戦略:** DINOベースのDiscriminatorを利用することでrFIDスコアが向上するものの、下流の生成品質の改善はそれほど大きくなく、大規模tokenizerへの適用時に不安定になることが観察されています。

私が考える追加の制限事項は以下の通りです。

*   **計算コスト:** 30億パラメータのtokenizerを訓練するには、依然として相当な計算リソースが必要です。
*   **汎化性能:** ImageNetのような特定のデータセットで優れた性能を発揮しますが、他の種類の画像やビデオデータへの汎化性能は不明です。
*   **アーキテクチャの最適化:** GigaTokのアーキテクチャは、CNNとTransformerのハイブリッドですが、最適なアーキテクチャであるとは限りません。より効率的なアーキテクチャが存在する可能性があります。
*   **tokenizerとARモデルの連携:** tokenizerとARモデルは別々に訓練されますが、両者を共同で最適化することで、さらに性能を向上させることができる可能性があります。
*   **解釈可能性:** tokenizerがどのように画像をエンコードしているのか、その内部表現の解釈は容易ではありません。

## 5. 技術的な詳細について。技術者が読むことを想定したトーンで

GigaTokの技術的な詳細について解説します。

*   **アーキテクチャ:** VQ-GANをベースとしたハイブリッドCNN-Transformerアーキテクチャを採用しています。encoderは、CNNブロックで空間解像度を段階的に削減し、TransformerレイヤーとVector Quantizerで離散潜在コードを生成します。decoderは、TransformerレイヤーとCNN decoderで構成され、潜在コードから画像を再構成します。
*   **1D Tokenizer:** encoderとdecoderのTransformerモジュールにQ-Formerを使用します。encoderのQ-Formerは、2Dの入力特徴量を1Dの潜在トークンに変換します。decoderのQ-Formerは、1Dの潜在トークンを2Dの特徴量に変換し、CNN decoderに渡して画像を再構成します。
*   **Semantic Regularization:** tokenizerのdecoderの中間層の特徴量`f_dec,l`と、事前学習済みのDINOv2モデルから抽出された特徴量`f_DINO`の類似度を最大化するように学習します。類似度関数にはcosine similarityを使用し、損失関数に加えます。これにより、tokenizerの潜在空間の複雑さを制限し、下流のARモデルが学習しやすい表現を獲得させます。
*   **Entropy Loss:** 2.9Bパラメータのtokenizerの学習を安定化させるために、entropy lossを使用します。entropy lossは、量子化誤差を減らすために量子化の不確実性にペナルティを課す項と、コードブックベクトルがより均一に選択されるようにする項から構成されます。

疑似コードで示すと以下のようになります。

```python
def calculate_vq_loss(encoder_output, codebook):
  """VQ損失を計算する
  Args:
    encoder_output: エンコーダの出力特徴量
    codebook: コードブックベクトル

  Returns:
    vq_loss: VQ損失
  """
  # encoder_outputを最も近いコードブックベクトルに量子化
  quantized_output, indices = quantize(encoder_output, codebook)

  # commitment loss：encoder_outputが量子化されたベクトルに近づくようにする
  commitment_loss = mse_loss(encoder_output, quantized_output.detach())

  # codebook loss：コードブックベクトルがencoder_outputに近づくようにする
  codebook_loss = mse_loss(quantized_output, encoder_output.detach())

  # VQ損失：commitment lossとcodebook lossの重み付き和
  vq_loss = beta * commitment_loss + codebook_loss
  return vq_loss, quantized_output, indices

def quantize(encoder_output, codebook):
  """encoder_outputをコードブックベクトルに量子化する
  Args:
    encoder_output: エンコーダの出力特徴量
    codebook: コードブックベクトル

  Returns:
    quantized_output: 量子化された特徴量
    indices: 最も近いコードブックベクトルのインデックス
  """
  # encoder_outputとコードブックベクトルの距離を計算
  distances = calculate_distances(encoder_output, codebook)

  # 最も近いコードブックベクトルのインデックスを取得
  indices = torch.argmin(distances, dim=-1)

  # 量子化された特徴量を作成
  quantized_output = codebook[indices]
  return quantized_output, indices

def calculate_distances(x, y):
    """
    Calculate Euclidean distances between each element of x and each element of y.
    Args:
        x: Tensor of shape (..., features)
        y: Tensor of shape (num_vectors, features)
    Returns:
        distances: Tensor of shape (..., num_vectors)
    """
    x_norm = torch.sum(x ** 2, dim=-1, keepdim=True)
    y_norm = torch.sum(y ** 2, dim=-1, keepdim=True)
    xy = torch.matmul(x, y.transpose(-2, -1))
    distances = torch.sqrt(torch.clamp(x_norm + y_norm.transpose(-2, -1) - 2 * xy, min=0.0))
    return distances
```

# In-2-4D: Inbetweening from Two Single-View Images to 4D Generation

[View Paper](http://arxiv.org/abs/2504.08366v1)

## 1. 既存研究では何ができなかったのか

既存研究における具体的な問題点は、この論文のabstractからは直接的には詳細に読み取れません。しかし、以下の点から既存研究の限界を推測できます。

*   **少数視点からの4D生成の困難さ:** 論文タイトルが「In-2-4D」であることから、既存研究では2つの単一視点画像からの4D（3D + motion）生成が困難であったと考えられます。
*   **大きなフレーム間モーションへの対応:** ビデオ補間モデルの利用に触れていることから、既存のビデオ補間技術では、フレーム間の大きなモーションを扱う際に曖昧な解釈が生じるという問題があったと考えられます。
*   **時間的な一貫性の維持:** 「時間的な一貫性を改善し、3Dモーションを洗練する」とあることから、既存手法では時間的な一貫性を保つことが難しかったと推測できます。
*   **スムーズな遷移の実現:** 独立して生成された3Dモーションセグメントのマージにおいて、スムーズでちらつきのない遷移を確保する必要があることから、既存手法ではセグメント間のスムーズな接続が難しかったと考えられます。

## 2. どのようなアプローチでそれを解決しようとしたか

この論文では、上記の課題に対して以下の複合的なアプローチで解決を試みています。

1.  **階層的キーフレーム選択:** まず、入力画像に近い視覚的特徴を持ち、かつ大きなモーションを示すキーフレームを階層的に特定します。これにより、全体的なモーションを段階的に捉え、曖昧さを軽減します。
2.  **Gaussian Splattingによる3D表現:** 各キーフレームの3D表現をGaussian Splattingを用いて構築します。これにより、高品質な3D再構成を実現します。
3.  **変形場による動的Gaussian変換:** キーフレーム間の時間的フレームを用いてモーションをガイドし、変形場を通じてGaussianを動的に変化させます。これにより、3D表現に時間的な変化（モーション）を組み込みます。
4.  **時間的整合性のためのSelf-Attention拡張:** マルチビュー拡散モデルのself-attentionを時間方向に拡張し、時間的な一貫性を強化します。
5.  **剛体変換正則化:** 3Dモーションを洗練するために、剛体変換の正則化を適用します。
6.  **変形場補間と最適化によるセグメントマージ:** 独立に生成された3Dモーションセグメントを、境界の変形場を補間し、ガイドビデオに合わせて最適化することで、スムーズにマージします。

疑似コードで表現すると、以下のようになります。

```python
def in_2_4d(image1, image2):
    # 1. キーフレーム選択
    keyframes = hierarchical_keyframe_selection(image1, image2)

    # 2. Gaussian Splattingによる3D表現
    gaussians = [gaussian_splatting(keyframe) for keyframe in keyframes]

    # 各セグメントに対して
    for i in range(len(keyframes) - 1):
        # 3. 変形場による動的Gaussian変換
        deformation_field = calculate_deformation_field(keyframes[i], keyframes[i+1])
        dynamic_gaussians = transform_gaussians(gaussians[i], deformation_field)

        # 4. 時間的整合性のためのSelf-Attention拡張
        dynamic_gaussians = temporal_attention(dynamic_gaussians)

        # 5. 剛体変換正則化
        dynamic_gaussians = rigid_transformation_regularization(dynamic_gaussians)

    # 6. 変形場補間と最適化によるセグメントマージ
    final_4d_model = merge_segments(dynamic_gaussians)
    return final_4d_model
```

# BlenderGym: Benchmarking Foundational Model Systems for Graphics Editing

[View Paper](http://arxiv.org/abs/2504.01786v1)

## 1. 既存研究では何ができなかったのか

既存研究は、3Dグラフィックス編集におけるVision-Language Model (VLM) の開発と評価において、以下の点で不十分でした。

*   **包括的なベンチマークの欠如:** 既存の評価方法は、特定のタスクに特化していたり、サンプルセットが限られていたため、異なるアプローチ間のクロス比較が困難でした。3Dグラフィックス編集は、オブジェクト配置、ライティング調整、マテリアル編集、形状操作、ジオメトリ編集など、多岐にわたるタスクを含みますが、これらを網羅的に評価できるベンチマークが存在しませんでした。
*   **信頼性の高い評価指標の不足:** グラフィックス編集の結果は、数学のように明確な正解がないため、人間による評価が一般的ですが、時間とコストがかかります。AIを評価者として使用する試みもありますが、AIモデル自体のバイアスや推論能力の限界から、信頼性に問題がありました。
*   **推論スケーリングの研究不足:** VLMの生成能力のスケーリングに関する研究は進んでいましたが、生成をガイドする検証器（Verifier）のスケーリングに関する研究は不足していました。また、生成と検証の間で計算リソースを最適に配分する方法についても不明な点が多くありました。
*   **VLMの人間の能力との比較の欠如:** VLMの性能を人間のBlenderユーザーと比較して、具体的なギャップを明確にすることができていませんでした。

## 2. どのようなアプローチでそれを解決しようとしたか

本研究では、上記の問題点を解決するために、以下の新しいアプローチを採用しました。

*   **BlenderGymの導入:** 3Dグラフィックス編集のための包括的なVLMシステムベンチマークであるBlenderGymを開発しました。BlenderGymは、Pythonコード編集を通じて3Dシーンを再構築するタスクを通じてVLMシステムを評価します。
*   **タスクの網羅性:** オブジェクト配置、ライティング調整、プロシージャルマテリアル編集、ブレンドシェイプ操作、プロシージャルジオメトリ編集という、3Dグラフィックス編集の5つの主要なタスクをカバーしています。
*   **定量的な評価:** 固定された開始シーンと目標シーンのペアを提供することで、人間やAIによる評価を必要とせずに、編集結果を定量的に評価できます。フォトメトリック損失 (PL)、CLIPスコア、Chamfer距離 (CD) などの指標を使用します。
*   **生成器-検証器構造:** VLMシステムを、提案を生成する生成器と、その提案を評価する検証器から構成される構造で評価します。この構造により、推論スケーリングの効果を検証器に適用できます。
*   **検証器のスケーリング:** 検証器の性能を向上させるために、複数回の検証クエリを実行し、その結果を統合するリセレクション機構を導入しました。
*   **リソース配分の最適化:** 生成と検証の間で計算リソースを戦略的に配分する方法を検討し、最適な配分比率を実験的に決定しました。
*   **人間との比較:** VLMシステムの性能を、Blenderに慣れた人間のユーザーと比較することで、VLMシステムの課題を明確にしました。

## 3. 結果、何が達成できたのか

BlenderGymを用いることで、以下の成果を達成しました。

*   **VLMシステムの定量的な評価:** 既存の最先端のVLMシステム (クローズドソースおよびオープンソース) をBlenderGymで評価し、人間ユーザーと比較して、VLMシステムが依然として3Dグラフィックス編集タスクに苦戦していることを明らかにしました。

## 4. Limitationや問題点は何か

本研究には、以下の制限事項と問題点があります。

*   **タスクとデータセットの拡張性:** BlenderGymのタスクは、オブジェクトスカルプティング、カメラビュー調整、アニメーション作成など、3Dグラフィックス編集のすべての側面を網羅しているわけではありません。また、データインスタンスの数も限られています。

## 5. 技術的な詳細について

*   **VLMシステムの構成:** VLMシステムは通常、生成器と検証器から構成されます。生成器は、BrainstormerとCode Editorの2つのコンポーネントを含みます。Brainstormerは、開始シーンと目標シーンのレンダリング画像を比較し、Pythonスクリプトの編集指示を生成します。Code Editorは、Brainstormerの指示に基づいてPythonスクリプトを編集します。検証器は、生成された編集候補を評価し、最適なものを選択します。

*   **推論スケーリング:** 検証器の性能を向上させるために、リセレクション機構を導入します。これは、複数回の検証クエリを実行し、その結果を統合することで、より正確な選択を行うことを目指します。
    ```python
    def ScaledSelect(proposals, verifier, reselection_param):
        """
        複数回の検証を行い、最適な提案を選択する関数

        Args:
            proposals: 編集候補のリスト
            verifier: 検証器
            reselection_param: 検証回数

        Returns:
            最終的に選択された編集候補
        """
        winner_list = []
        for _ in range(reselection_param):
            shuffled_proposals = shuffle(proposals)
            winner = SingleSelect(shuffled_proposals, verifier) # 1回の検証で選択
            winner_list.append(winner)
        final_winner = SingleSelect(winner_list, verifier) # 最終的な選択
        return final_winner
    ```

*   **評価指標:**
    *   **フォトメトリック損失 (PL):** 生成された画像と目標画像の間のピクセル単位の色の差を測定します。
    *   **CLIPスコア:** 生成された画像と目標画像の間の意味的な類似性を測定します。
    *   **Chamfer距離 (CD):** 生成された3Dモデルと目標の3Dモデル間の点群の距離を測定します。

*   **Blender-Python API (BPY) の活用:** プロシージャルなマテリアルおよびジオメトリ編集タスクでは、Blender-Python API と Infinigen パッケージを使用しています。これにより、VLM システムはコード編集を通じて複雑な3Dモデルを生成および編集できます。

    *   Multimodal Rotary Position Embedding (MM-RoPE) を使用して、テキストとビデオ間の位置情報を効果的に融合します。

    *   Runtime Balance により、画像とビデオの同時トレーニングにおけるGPU間の負荷分散を最適化します。
    *   Multi-Level Activation Checkpointing (MLAC) により、GPUメモリ使用量を削減し、再計算オーバーヘッドを最小限に抑えます。
    *   Kernel Fusion技術により、メモリへのアクセス集中型演算を最適化し、トレーニング効率を向上させます。
*   **推論:**
    *   Trajectory Segmented Consistency Distillation (TSCD) メソッドを採用し、推論に必要なステップ数を削減します。
    *   Classifier-Free Guidance (CFG) 埋め込みモジュールを設計し、CFG蒸留を実行して、CFGによる非効率性を排除します。
    *   敵対的トレーニングにより、少数ステップ推論によって生じるぼやけを軽減します。

```python
def mlac_forward(module, input):
  """
  Multi-Level Activation Checkpointingの前向き伝播。

  Args:
    module: 勾配チェックポイントの対象となるモジュール。
    input: モジュールの入力テンソル。

  Returns:
    moduleの出力。
  """
  # 計算負荷の高い演算からの出力をGPUに保存する
  output = module(input)

  # 入力テンソルをCPUまたはディスクにオフロードする
  offload_input(input)

  return output

def mlac_backward(module, output_grad):
  """
  Multi-Level Activation Checkpointingの後向き伝播。

  Args:
    module: 勾配チェックポイントの対象となるモジュール。
    output_grad: 出力の勾配。

  Returns:
    入力の勾配。
  """
  # オフロードされた入力を取得する
  input = retrieve_input()

  # 出力テンソルを再計算する必要がないので、逆伝播を行う
  input_grad = torch.autograd.grad(output, input, grad_outputs=output_grad)[0]

  return input_grad
```

# ModernBERT or DeBERTaV3? Examining Architecture and Data Influence on Transformer Encoder Models Performance

[View Paper](http://arxiv.org/abs/2504.08716v1)

## 1. 既存研究では何ができなかったのか

ModernBERTの著者らは、DeBERTaV3と比較してベンチマークで優れた結果を報告していますが、以下の点が不明確でした。

*   **トレーニングデータの透明性の欠如:** ModernBERTのトレーニングに使用されたデータセットの詳細が開示されていませんでした。
*   **共通データセットでの比較の欠如:** 異なるモデルが同じデータセットで比較されていなかったため、アーキテクチャの改善とトレーニングデータの違いのどちらが性能向上に寄与しているかを判断できませんでした。
*   **ベンチマーク飽和の可能性:** 既存のベンチマークが、モデルのわずかな改善を正確に評価できない可能性がありました。

## 2. どのようなアプローチでそれを解決しようとしたか

以下の制御された実験アプローチを採用しました。

*   **同一データセットでの事前学習:** ModernBERTを、DeBERTaV3のフランス語モデルであるCamemBERTaV2と同じデータセットで事前学習させ、モデル設計の影響を分離しました。
*   **高品質データセットでの事前学習:** ModernBERTの別のバリアントを、厳選された高品質なフランス語コーパスで事前学習させ、データセットの品質がモデルのパフォーマンスに与える影響を調査しました。
*   **中間チェックポイントの利用:** CamemBERTaV2およびCamemBERTv2モデルの公開されている中間チェックポイントを利用して、学習軌跡とデータ効率を比較しました。
*   **ベンチマーク評価:** モデルをフランス語の様々なダウンストリームタスクとデータセットで評価し、アーキテクチャとトレーニングデータの影響を分析しました。具体的には、FLUEベンチマーク（分類、言い換え識別、推論タスクを含む）や質問応答タスク（FQuAD）などを利用しました。

## 3. 結果、何が達成できたのか

以下の成果が得られました。

*   **DeBERTaV3の優位性:** データセットを制御した場合、DeBERTaV3は、全体的なベンチマークパフォーマンスとトレーニングサンプル効率においてModernBERTを上回りました。DeBERTaV3のアーキテクチャとトレーニング目標の最適化が、ModernBERTの効率重視の設計よりも優れた学習能力を提供することを示唆しています。
*   **ModernBERTの利点:** ModernBERTは、トレーニングと推論の速度が大幅に速いため、実用的な利点があります。また、BERTやRoBERTaなどの以前のトランスフォーマーモデルと比較して、有意義なアーキテクチャの改善を提供します。
*   **高品質データの効果:** 高品質でフィルタリングされたデータセットでモデルをトレーニングすると、収束が速まりますが、最終的なパフォーマンスメトリックは大幅には向上しませんでした。これは、現在のNLPベンチマークが飽和状態に達している可能性を示唆しています。
*   **学習ダイナミクスの分析:** QAタスクとNERタスクにおける中間チェックポイントの評価により、学習ダイナミクスの詳細なビューが得られました。DeBERTaV3ベースのモデルは、トレーニングの初期段階でより高いパフォーマンスに到達し、RTDやGDESなどの最適化によるサンプル効率の向上が確認されました。
*   **モデルの公開:** CamemBERTaV2データセットでトレーニングされたバリアントと、高品質のフィルタリングされたコーパスでトレーニングされたバリアントを含む、事前トレーニング済みのフランス語ModernBERTモデルを公開しました。

## 4. Limitationや問題点は何か

*   **ベンチマークの飽和:** 現在のベンチマークが、モデルのパフォーマンスのわずかな改善を正確に評価できない可能性があります。
*   **ハイパーパラメータの感受性:** ModernBERTは、ファインチューニングの安定性が低く、ハイパーパラメータの選択に特に敏感でした。QAタスクで発散するケースが見られました。
*   **エンジニアリングの最適化:** DeBERTaモデルには、ModernBERTで行われた、アンパディングやFlashAttentionなどのエンジニアリング最適化が実装されていませんでした。これらの最適化は、速度の向上に大きく貢献している可能性があります。
*   **データセットのバイアス:** 公開されているデータセットを使用していますが、依然としてデータセット内のバイアスがモデルに反映される可能性があります。
*   **評価タスクの限定性:** フランス語のタスクに限定されているため、他の言語やタスクにおけるパフォーマンスは不明です。

## 5. 技術的な詳細について

*   **アーキテクチャ:** ModernBERTは、BERTアーキテクチャを最新化するために、効率を重視した設計が組み込まれています。具体的には、グローバルおよびローカルアテンションレイヤーの交互配置、ロータリーポジショナルエンベディング（RoPE）の採用、バイアス項の削除、GeGLUアクティベーションの導入などが含まれます。

# CoRAG: Collaborative Retrieval-Augmented Generation

[View Paper](http://arxiv.org/abs/2504.01883v1)

## 1. 既存研究では何ができなかったのか

既存の研究は、Retrieval-Augmented Generation (RAG) モデルを集中型の環境に限定していました。つまり、単一の主体がモデルとデータストアの両方を管理する状況を想定していました。複数のクライアントがラベル付きデータを直接共有することなく、共有モデルを共同で訓練する、協調学習フレームワークにおけるRAGの可能性は、ほとんど探求されていませんでした。特に、クライアント間で共有されたパッセージストアを構築し、それを利用する際の課題やクライアントのインセンティブについては未解明な点が多かったのです。

## 2. どのようなアプローチでそれを解決しようとしたか

CoRAG (Collaborative RAG) というフレームワークを提案することで、この問題に対処しました。CoRAGは、複数のクライアントが共同でパッセージストアを構築し、それを利用して共有モデルを訓練することを可能にします。各クライアントは推論時にローカルのパッセージストアも使用できます。さらに、CRAB (Collaborative Retrieval-Augmented Benchmark) という新しいベンチマークを導入し、協調的なオープンな質問応答タスクを評価しました。パッセージストアの構成 (関連パッセージ、無関係なパッセージ、ハードネガティブパッセージ) がモデルの性能に与える影響を分析し、クライアントの参加を促すインセンティブメカニズムについて考察しました。

## 3. 結果、何が達成できたのか

CRABベンチマークを用いた実験により、CoRAGは、リソースが限られた状況において、従来のパラメトリックな協調学習手法やローカルで訓練されたRAGモデルを上回る性能を発揮することが示されました。特に、共有ストア内の関連パッセージの重要性、無関係なパッセージを組み込むことによる意外な利点、ハードネガティブが性能に悪影響を及ぼす可能性を明らかにしました。このことは、協調的なRAGにおける、集合的に強化された知識ベースを活用することと、他のクライアントからの有害なパッセージを取り込むリスクとのトレードオフという、新たな考慮事項を導入しました。

## 4. Limitationや問題点は何か

*   **均質なデータ分布の仮定:** 実験は、クライアントが同一のデータ分布を持つ均質な環境に限定されています。現実の協調的なシナリオでは、クライアントが異なるソース、ドメイン、またはさまざまな品質レベルのデータを持つことが多いため、異質なデータ分布におけるCoRAGの有効性と公平性を評価する必要があります。
*   **スケーラビリティ:** 実験は、8つのクライアントという比較的小規模で行われています。より多くのクライアントにCoRAGをスケールさせる場合、通信効率、モデル集約、大規模なパッセージストアの処理など、課題が生じます。
*   **インセンティブメカニズムの未確立:** 貢献ベースの報酬、段階的なアクセスレベル、評判システムなど、クライアントの貢献を促すインセンティブメカニズムを提案していますが、これらのメカニズムの設計、評価、および展開には、さらなる調査が必要です。
*   **バイアスのリスク:** 複数のクライアントによって共同で構築された共有パッセージストアは、個々のクライアントが保持するデータに存在するバイアスを反映してしまう可能性があります。
*   **悪用の可能性:** CoRAGの機能は、有害または誤解を招くコンテンツの生成など、悪意のある目的に悪用される可能性があります。

## 5. 技術的な詳細について

CoRAGの実装は、以下の要素で構成されます。

*   **Retriever:** 入力クエリに基づいて、パッセージストアから関連するドキュメントを検索します。実験ではBM25が用いられています。
*   **Reader:** Retrieverによって検索されたドキュメントと入力クエリに基づいて、最終的な出力を生成します。実験では、Fusion-in-Decoderを搭載したT5ベースモデルが使用されています。
*   **Collaborative Passage Store:** 複数のクライアントから提供されたテキストパッセージのコレクションです。トレーニングとテストには個別のパッセージストアが使用されます。

**トレーニング手順:**

1.  **Pretraining:** RetrieverとReaderは、大規模な共有データセットで自己教師あり学習を用いて事前学習されます。
2.  **Collaborative Finetuning:** クライアントは、ローカルのトレーニングデータセットで、事前学習済みのRetrieverとReaderを協調的にファインチューニングします。このとき、共有されたパッセージストアから関連するパッセージを検索します。
3.  **Model Aggregation:** クライアントのモデルアップデートは、FedAvgなどの手法を使用して、分散型または集中型の方法で集約され、協調的なトレーニング中に得られた集合的な知識を反映するグローバルモデルが生成されます。
4.  **Inference:** クライアントは、協調的にトレーニングされたグローバルRAGモデルを使用して、入力クエリを処理します。各クライアントは、ローカルのテストパッセージストアから関連するパッセージを特定することにより、ローカルの質問応答メトリックを最大化することを目指します。

**疑似コード (PyTorch風):**

```python
class CoRAG(nn.Module):
    def __init__(self, retriever, reader):
        super().__init__()
        self.retriever = retriever
        self.reader = reader

    def forward(self, query, passage_store):
        # 1. Retrieve relevant passages
        retrieved_passages = self.retriever(query, passage_store)

        # 2. Generate output using retrieved passages and query
        output = self.reader(query, retrieved_passages)

        return output

def train_corag(model, datasets, optimizer, passage_store, aggregation_method="FedAvg"):
    # Training loop for each client
    client_models = []
    for dataset in datasets:
        # Finetune model on local dataset with passages from passage_store
        client_model = finetune(model, dataset, passage_store, optimizer)
        client_models.append(client_model)

    # Aggregate client models (e.g., using FedAvg)
    if aggregation_method == "FedAvg":
        aggregated_model = fedavg(client_models)
    else:
        aggregated_model = aggregate(client_models) # Custom aggregation method

    return aggregated_model
```

# Latent Diffusion Autoencoders: Toward Efficient and Meaningful Unsupervised Representation Learning in Medical Imaging

[View Paper](http://arxiv.org/abs/2504.08635v1)

## 1. 既存研究では何ができなかったのか

既存のdiffusion-basedな手法は、主に画像生成と編集に焦点が当てられており、表現学習能力（representation learning）の研究は限られていました。特に3D MRI脳画像のような高次元データに対して、以下の点が課題でした。

*   **計算効率**: 従来のDiffusion Autoencoders (DAEs) は画像空間でdiffusionプロセスを行うため、計算コストが高く、3D医療画像への適用が困難でした。
*   **意味のある潜在表現の学習**: 従来のDPMs（Diffusion Probabilistic Models）は高品質な画像を生成できますが、得られる潜在表現はsemanticな意味が薄く、属性の操作や補間が難しいという問題がありました。
*   **3D医療画像におけるUnsupervised表現学習**: 3D MRI脳画像領域において、diffusionモデルを用いたunconditional/conditional生成や、既存の脳構造特徴を用いたdisease progression predictionの研究は存在しましたが、diffusionモデルによるunsupervisedな表現学習で、複雑な3D脳構造を捉えるsemantic表現を獲得する試みはほとんどありませんでした。

## 2. どのようなアプローチでそれを解決しようとしたか

本研究では、これらの課題を解決するために、Latent Diffusion Autoencoder (LDAE) という新しいencoder-decoder diffusion-basedフレームワークを提案しました。

1.  **Latent空間でのDiffusion**: 画像空間ではなく、圧縮されたlatent空間でdiffusionプロセスを行うことで、計算効率を大幅に向上させ、3D医療画像表現学習をtractableにしました。
2.  **Perceptual Autoencoder (AE) による次元削減**: 高次元MRIスキャンを低次元latent空間へ圧縮し、処理効率を高めました。
3.  **Latent Diffusion Model (LDM) の事前学習**: 圧縮されたlatent表現の分布を学習させることで、よりsemanticな情報を保持した潜在空間を構築しました。
4.  **Encoder-Decoder構造によるposterior mean gapの補完**: Diffusion Autoencoder (DAE) のencoder-decoder構造を導入し、encoderで抽出したsemanticな特徴を用いてdecoderをguidanceすることで、latent表現の意味を高めました。具体的には、PDAE (Pretrained Diffusion Autoencoders) で提案されたposterior mean gapを埋める戦略に従い、pretrainedなdiffusionモデルにencoder-decoderを追加学習させました。
5.  **Semantic Encoderによるguidance**: 事前学習済みのLDMをfrozenにし、semantic encoderで抽出された特徴を用いてconditionalなdecoderを学習させ、semanticな属性に基づいた生成を可能にしました。このdecoderは、gradient estimatorとして機能し、pretrainedなDDPM (Denoising Diffusion Probabilistic Model) の生成をguidanceします。

## 3. 結果、何が達成できたのか

提案手法であるLDAEにより、以下の成果が達成されました。

*   **計算効率の大幅な向上**: 従来のDAEと比較して、推論スループットが20倍高速化されました。
*   **高画質な画像生成・再構成**: 計算効率を向上させながらも、従来のDAEと同等以上の再構成品質を達成しました。
*   **意味のあるsemantic表現の学習**: 線形プローブ評価において、AD診断（ROC-AUC: 90%, ACC: 84%）および年齢予測（MAE: 4.1 years, RMSE: 5.2 years）で有望な診断性能を示しました。
*   **属性操作による解剖学的に妥当なmodification**: 学習されたsemantic表現を用いて属性操作を行うことで、解剖学的に妥当なmodificationを実現しました。例えば、AD患者の脳MR画像を、CN（健常者）に近づけるようなmodificationが可能となりました。
*   **Semantic補間による欠損スキャンの高精度再構成**: semantic補間実験により、欠損したスキャンを高精度に再構成できることが示されました。6ヶ月のギャップに対してSSIM 0.969 (MSE: 0.0019)、24ヶ月のギャップに対してもSSIM > 0.93 (MSE < 0.004) を維持し、時間的進行傾向を捉える能力が示されました。

## 4. Limitationや問題点は何か

本研究には、以下のLimitationsや問題点が存在します。

*   **再構成品質のボトルネック**: 最終的な生成画像の品質は、Perceptual Autoencoder (AutoencoderKL) の再構成品質に依存しており、完全な解像度でのlosslessな再構成が不可欠です。AutoencoderKLの圧縮がLDDIM, LDAEの性能の上限となっているため、AutoencoderKL自体の性能向上が必要です。
*   **線形補間の仮定**: 脳の進化は非線形なプロセスであるため、現在の補間方法 (LERP, SLERP) は脳の老化の進行を正確に表現できていない可能性があります。semantic空間内で明示的に学習された高度な回帰モデルや予測モデルを組み込むことで、より現実的な脳の老化の進行を近似できる可能性があります。
*   **臨床的検証の必要性**: 生成された画像は臨床専門家によってqualitativelyに検証されていますが、より厳密な臨床研究による検証が必要です。多様な母集団、様々なスキャナ、様々なdisease phenotypeに渡る検証が必要です。
*   **表現のdisentanglement**: 潜在空間におけるdisease stateとageの潜在的な相関を考慮すると、ロバストで解釈可能な属性操作を保証するためには、体系的なmulti-attribute disentanglement分析が不可欠です。
*   **生成AI利用に関する記述**: 論文作成中にChatGPTを使用しており、その影響を完全に排除できない可能性があります。

## 5. 技術的な詳細について

LDAEは、以下の3つの主要なコンポーネントで構成されています。

1.  **Perceptual Autoencoder (AE)**: 高次元の3D MRI脳画像を低次元のlatent空間に圧縮します。encoder `E` と decoder `D` から構成され、以下の式で表現できます。

    ```python
    z_0 = E(x_0) # x_0は入力画像, z_0は圧縮されたlatent表現
    x_0_reconstructed = D(z_0) # x_0_reconstructedは再構成された画像
    ```

    学習には、Perceptual LossとKullback-Leibler (KL) 正則化が用いられます。

2.  **Latent Diffusion Model (LDM)**: 圧縮されたlatent表現の分布を学習するdiffusionモデルです。DDPM (Denoising Diffusion Probabilistic Model) またはDDIM (Denoising Diffusion Implicit Model) を用いて、latent空間上でnoiseを加えるforward processと、noiseを除去するreverse processを学習します。

    *   **Forward Process (Diffusion)**: 画像 `x_0` に徐々にGaussian noiseを加えていき、最終的にisotropic Gaussian distribution `x_T` に近づけます。

        ```python
        # アルファとベータはnoise schedule
        x_t = sqrt(alpha_bar_t) * x_0 + sqrt(1 - alpha_bar_t) * noise
        ```

    *   **Reverse Process (Denoising)**: noiseから徐々にnoiseを除去していき、最終的に画像を生成します。

        ```python
        # epsilon_thetaはnoiseを予測するU-Netベースのモデル
        x_t_minus_1 = ... #  x_tからnoiseを除去した画像
        ```

3.  **Semantic Encoder & Gradient Estimator**: 画像のsemanticな情報を抽出するencoderと、LDMのreverse processをguidanceするgradient estimatorから構成されます。Semantic Encoder `Enc_phi` は、3D脳画像を2D axial sliceのシーケンスとして扱い、各sliceを2D CNNでembeddingした後、soft-attentionとcross-attentionを用いてglobalなsemantic vectorを生成します。Gradient Estimator `G_psi` は、pretrainedなLDMのU-Netアーキテクチャを再利用し、semantic vectorを用いてconditionalなdenoisingを行います。

    ```python
    y_sem = Enc_phi(x_0) # x_0は入力画像, y_semはsemantic vector

    # Gradient EstimatorはU-Netベースのモデル
    # z_tはnoiseが加えられたlatent表現
    # tはdiffusion step
    gradient = G_psi(z_t, y_sem, t)

    # 逆diffusion過程における更新
    z_t_minus_1 = ... #  z_tからgradientを使ってnoiseを除去したlatent表現
    ```

LDAEの学習は、pretrainedなLDMをfrozenにした状態で、semantic encoderとgradient estimatorをjointに最適化することで行われます。

# MineWorld: a Real-Time and Open-Source Interactive World Model on Minecraft

## 1. 既存研究では何ができなかったのか

既存のビデオ生成モデルは、効率性と制御可能性の点で課題がありました。

*   **効率性の問題:** 既存のビデオ生成モデルは、ビデオの潜在表現（視覚トークナイザによってエンコードされたもの）に含まれるトークン数が非常に多いため、推論時の計算コストが大きくなります。これにより、モデルとのリアルタイムなインタラクションが困難になっていました。
*   **制御可能性の問題:** モデルが与えられた制御信号に基づいて正確な結果を生成することが難しいという課題がありました。テキスト記述やロボットアームの動きなど、様々な制御信号がありますが、生成された結果が入力信号にどれだけ忠実であるかを定量化する標準化されたメトリックが不足していました。

## 2. どのようなアプローチでそれを解決しようとしたか

本研究では、これらの課題を克服するために、Minecraftを舞台としたリアルタイムインタラクティブなワールドモデル「MineWorld」を提案しました。

*   **効率性の向上:**
    *   視覚的なゲームシーンとアクションを離散的なトークン表現に変換し、それらをモデルへの入力として連結することで、明示的に視覚状態と制御信号の間の相関関係を学習するように設計しました。
    *   Transformerの自己回帰生成を大幅に加速する新しい並列デコーディングアルゴリズムを導入しました。このアルゴリズムは、空間的に隣接するトークン間の依存関係を利用して、一部のトークングループを並行して予測できるようにします。
*   **制御可能性の評価:**
    *   従来のビデオ品質評価を超えた新しい評価メトリックを提案しました。
    *   Minecraftでのアクションを離散的なトークンに変換し、生成されたビデオから逆動力学モデル (IDM) を使用してアクションを予測します。IDMによって予測されたアクションと、入力として与えられた真のアクションとの精度を比較することで、生成モデルの制御可能性を評価します。

## 3. 結果、何が達成できたのか

MineWorldによって、以下の成果が達成されました。

*   **リアルタイムインタラクション:** 新しい並列デコーディングアルゴリズムにより、モデルは毎秒4〜7フレームを生成できるようになり、ゲームプレイヤーとのリアルタイムインタラクションが可能になりました。標準的な自己回帰デコーディングと比較して大幅な高速化を達成しました。
*   **高精度な制御:** 提案された評価指標を用いて、生成されたゲーム状態が提供されたアクションと前の状態にどれだけ一致しているかを評価しました。
*   **既存研究を凌駕:** 包括的な評価により、MineWorldが既存の最先端のオープンソース拡散ベースワールドモデルを大幅に上回ることが示されました。
*   **コードとモデルの公開:** 研究の再現性とさらなる発展を促進するため、コードとモデルが公開されました。
*   **自己完結型ゲームエージェントとしての可能性:** MineWorld はゲーム状態のトークンとアクションのトークンを両方予測することで、ワールドモデルとポリシーモデル両方の機能を取得し、自身でゲームをプレイできるゲームエージェントとしての可能性を示しました。

## 4. Limitationや問題点は何か

MineWorldにはいくつかの制限事項と課題があります。

*   **一般化能力の欠如:** MineWorldは、特定の解像度でダウンサンプリングされたMinecraftデータのみでトレーニングされているため、他のビデオドメイン（インターネットビデオなど）への一般化や、より高い解像度での出力生成能力が制限されます。
*   **細部の損失:** ダウンサンプリング処理により、ゲーム状態の微細なディテールが失われる可能性があります。
*   **長期的な一貫性の欠如:** モデルの最大入力長は16のstate-actionペアに設定されています。この範囲内では強力な時間的一貫性が実証されていますが、ゲーム状態間の距離がこの範囲を超えると、一貫性が保証されません。
*   **アクション空間の簡略化:** アクション実行の品質を効果的に検証するために、最も一般的な10個のアクションとカメラの動きに焦点を当ててシナリオを簡略化しました。
*   **計算コスト:** 大規模なTransformerモデルを使用しているため、学習と推論には依然として高い計算コストが必要です。
*   **IDM の精度への依存:** 制御可能性の評価は、使用する逆動力学モデル (IDM) の精度に依存します。IDM の精度が低い場合、制御可能性の評価結果も不正確になる可能性があります。
*   **並列デコーディングの性能劣化:** 並列デコーディングを利用することで高速化を実現していますが、トレーニング時と推論時における処理の違いから、結果の品質が若干低下する可能性があります。

## 5. 技術的な詳細について

MineWorldは、視覚-アクション自己回帰型Transformerによって駆動されます。以下に技術的な詳細を説明します。

1.  **アーキテクチャ**:
    *   **Visual and Action Tokenizers:** ゲームの状態とアクションを離散的なトークンIDに変換します。
        *   **Visual Tokenizer (VQ-VAE):** 画像レベルのVQトークナイザを使用。各状態を独立してトークンに変換。空間圧縮を使用（高さと幅に対して圧縮率4）。公開されている事前学習済みのチェックポイントから初期化し、Minecraftデータセットで微調整。
        *   **Action Tokenizer:** カメラの角度を離散的なビンに量子化。相互排他的なアクションペア（例：前進と後退は同時には発生しない）を複数の排他的クラスに分類。各クラスは一意のトークンで表現。カメラの角度をエンコードするための追加トークンと、アクションシーケンスの境界をマークするための特殊トークンを導入。各アクションは一連のトークンとして表現されます。
    *   **Transformer Decoder (LLaMA):** LLaMAアーキテクチャに基づいており、root mean square layer normalizationが組み込まれています。各トークンは前のすべてのトークンを条件として予測される自己回帰的な方法で学習します。ゲーム状態とアクションのトークンを同等に扱い、それらのインタリーブ構造を学習できるようにします。これにより、状態とアクションの条件付き関係を捉え、ポリシーモデルとしても機能することが可能になります。
2.  **学習**:
    *   **目的関数:** 次のトークン予測による自己回帰学習。
        ```python
        def autoregressive_loss(tokens, model):
            # tokens: 入力トークンシーケンス
            # model: Transformerデコーダモデル
            loss = 0
            for i in range(1, len(tokens)):
                # 以前のトークンに基づいて次のトークンを予測
                predictions = model(tokens[:i])  # 最初のトークンからi-1番目までのトークンを入力
                # 真の次のトークンに対する損失を計算
                loss += cross_entropy(predictions, tokens[i])
            return loss
        ```
3.  **並列デコーディング (Diagonal Decoding):**
    *   空間的に隣接する画像トークン間の依存関係を利用して、トレーニング不要の並列デコーディングアルゴリズムを使用します。
    *   トークンを順番に予測するのではなく、隣接する行と列のトークンを同時に処理します。
    *   パッチ化されたゲーム状態の高さと幅をh, wとすると、並列デコーディングと自己回帰デコーディングの理論的な高速化率は、r = (h * w) / (h + w - 1)で表されます。
    *   並列アテンションマスクを用いたファインチューニングにより性能劣化を抑制。
4.  **評価**:
    *   **ビデオ品質**: Fréchet Video Distance (FVD), Learned Perceptual Image Patch Similarity (LPIPS), Structural Similarity Index Measure (SSIM)などの一般的な指標を使用します。
    *   **制御可能性**: 逆動力学モデル(IDM)を使用して、生成された状態からアクションを推測します。IDMは双方向モデルであり、ゲーム状態を入力として受け取り、それらの間のアクションを予測します。アクションラベルの不均衡と、離散アクションと連続アクションの混合を考慮して、分類ベースの評価指標とカメラ移動のL1損失を組み合わせて使用します。
5.  **アクション空間の離散化:**
    *   連続的なマウスの動き（カメラの角度を制御）と、キーボードやマウスの押下（ゲームエンジンで定義された離散的なアクション）を扱います。
    *   カメラの角度を離散的なビンに量子化します。

# SpecReason: Fast and Accurate Inference-Time Compute via Speculative Reasoning

[View Paper](http://arxiv.org/abs/2504.07891v1)

## 1. 既存研究では何ができなかったのか

既存研究は、推論時の計算量を増やして複雑なタスクの性能を向上させることに成功しましたが、以下の点で課題がありました。

*   **高い推論遅延:** 長い思考連鎖(CoT)を生成するLRM(Large Reasoning Model)の推論において、生成される推論シーケンスの長さと、LLMの自己回帰的な復号処理のために、推論遅延が大きくなってしまう。
*   **近似に対する寛容性の活用不足:** LRM推論の過程で、複雑なタスクはより単純なステップに分解されるが、各ステップで生成されるトークン列の正確さよりも、下流のステップに提供するセマンティックな洞察の方が重要であるという特性を、既存研究では十分に活用できていなかった。つまり、推論の各段階における近似に対する寛容性を活かせていなかった。
*   **推論ステップレベルでの最適化の欠如:** 従来の推論高速化手法（投機的デコーディングなど）は、トークンレベルでの等価性を要求していたため、中間的な推論ステップの近似に対する寛容性を十分に活用できていなかった。

## 2. どのようなアプローチでそれを解決しようとしたか

SpecReasonは、上記の課題を解決するために、以下の3つの主要なアプローチを採用しました。

1.  **軽量モデルによる推論ステップの投機的実行:**
    *   大規模な推論モデル(LRM)の推論を高速化するために、軽量なモデルを用いて、より単純な中間的な推論ステップを(投機的に)実行する。
    *   計算コストの高いベースモデルは、投機的に生成された出力の評価（および必要に応じて修正）のためにのみ使用する。
2.  **セマンティックな柔軟性の活用:**
    *   推論トークンのセマンティックな柔軟性を活用し、最終的な回答の精度を維持することに焦点を当てる。
    *   従来の投機的デコーディングのように、各ステップでトークンレベルの等価性を要求するのではなく、推論における近似に対する寛容性を利用する。
3.  **階層的な投機によるさらなる高速化:**
    *   SpecReasonと投機的デコーディングを組み合わせることで、階層的な投機スキームを実現し、さらなる遅延削減を可能にする。SpecReasonで推論ステップレベルでの投機を行い、ベースモデルによる再生成時に投機的デコーディングを適用する。

疑似コードで表すと以下のようになります。

```python
def spec_reason(task, base_model, small_model, acceptance_threshold):
    cot_prefix = ""  # 現在までの思考連鎖
    while not is_task_completed(cot_prefix):
        # 軽量モデルによる次のステップの投機
        speculated_step = small_model.generate_next_step(cot_prefix)

        # ベースモデルによる投機されたステップの評価
        utility_score = base_model.evaluate_step(cot_prefix, speculated_step)

        if utility_score >= acceptance_threshold:
            # 投機されたステップを受け入れる
            cot_prefix += speculated_step
        else:
            # 投機されたステップを拒否し、ベースモデルで再生成
            regenerated_step = base_model.generate_next_step(cot_prefix)
            cot_prefix += regenerated_step

    final_answer = base_model.generate_final_answer(cot_prefix)
    return final_answer

```

## 3. 結果、何が達成できたのか

SpecReasonは、様々な推論ベンチマークにおいて、以下の成果を達成しました。

*   **高速化:** バニラのLRM推論と比較して、1.5〜2.5倍の高速化を達成。
*   **精度向上:** 精度を1.0〜9.9%向上。
*   **投機的デコーディングとの組み合わせによるさらなる高速化:** SpecReasonなしの投機的デコーディングと比較して、19.4〜44.2%の遅延削減。

## 4. Limitationや問題点は何か

SpecReasonの制限事項と問題点は以下のとおりです。

*   **ベースモデルの評価オーバーヘッド:** 各ステップでベースモデルの検証が必要となるため、検証のオーバーヘッドが大きくなると、レイテンシが増加する可能性がある。論文では軽量な検証手法(single-token scoring)を採用しているが、より複雑な検証手法を導入する場合はオーバーヘッドを考慮する必要がある。
*   **軽量モデルの性能:** 軽量モデルの性能が低い場合、投機的ステップの拒否率が高くなり、ベースモデルによる再生成が増えるため、高速化の効果が薄れる可能性がある。特に、タスクの難易度が高い場合や、ベースモデルと軽量モデルの性能差が大きい場合に顕著になる。
*   **検証の静的閾値:** 静的な閾値を使用しているため、タスクやステップの難易度に応じて動的に閾値を調整することができない。より高度な検証手法（logprobsベースの信頼度推定や動的閾値など）を導入することで、性能をさらに改善できる可能性があるが、検証のオーバーヘッドが増加する可能性がある。
*   **ハードウェアリソース:** 軽量モデルとベースモデルを同一GPU上に配置しているため、GPUメモリの制約を受ける可能性がある。大規模なモデルを使用する場合や、複数のモデルを同時に実行する場合は、GPUメモリの最適化が重要となる。
*   **タスク依存性:** 論文では、数学の問題解決や一般的な知識を必要とする質問応答タスクで評価を行っているが、他の種類の推論タスク（例えば、常識推論や計画立案など）における有効性は検証されていない。
*   **汎用性の検証不足:** 異なるモデルアーキテクチャやデータセットに対するSpecReasonの汎用性については、さらなる検証が必要である。
*   **軽量モデルとベースモデルの性能バランス:** 軽量モデルとベースモデルの性能バランスが重要であり、最適なバランスを見つけるためには、タスクやモデルの特性に応じた調整が必要となる。

## 5. 技術的な詳細について

SpecReasonは、以下の技術的な要素で構成されています。

1.  **モデル構成:**
    *   ベースモデル： 高精度だが計算コストの高い大規模言語モデル(LRM)。論文では、QwQ-32B, R1-70Bなどが使用されている。
    *   軽量モデル： 高速だが精度が低い小型言語モデル。論文では、R1-1.5Bなどが使用されている。
2.  **推論プロセス:**
    *   軽量モデルが現在の思考連鎖(CoT)に基づいて次の推論ステップを投機的に生成。
    *   ベースモデルが、軽量モデルによって生成されたステップの有用性を評価。評価は、通常、CoTのプレフィックスを再利用したプロンプトを用いて、単一のトークン「スコア」を生成することで行われる。
    *   スコアが事前に定義された閾値を超えた場合、投機的ステップが受け入れられ、CoTに追加される。
    *   スコアが閾値を下回った場合、投機的ステップは破棄され、ベースモデルがステップを再生成する。
3.  **検証メカニズム:**
    *   論文では、ベースモデルにユーティリティスコア（例：0-9）を生成させることによって、投機的ステップの有用性を評価。
    *   評価プロンプトは、CoTプレフィックスの大部分を再利用するようにテンプレート化されているため、各検証に必要なプレフィルのトークン数は少ない（約70トークン）。
    *   静的な受容閾値を使用して、投機的ステップを受け入れるかどうかを決定。
4.  **ハードウェア実装:**
    *   軽量モデルとベースモデルを同じGPU上に配置。
    *   KVキャッシュ用に予約されたメモリは、2つのモデル間で静的に分割。
    *   推論は順番に実行され、軽量モデルとベースモデルが交互に処理を行う。
5.  **階層的投機:**
    *   SpecReasonと投機的デコーディングを組み合わせることで、階層的な投機システムを構築。
    *   SpecReasonはステップレベルの投機的推論を適用して、推論ステップをドラフトして検証。
    *   ステップが拒否されてベースモデルによって再生成された場合、標準的なトークンレベルの投機的デコーディングをベースモデルの再生成中に適用して、デコーディングをさらに高速化。

疑似コードで表すと以下のようになります。

```python
def evaluate_step(base_model, cot_prefix, speculated_step):
  """ベースモデルを使用して、投機されたステップの有用性を評価する"""
  prompt = create_evaluation_prompt(cot_prefix, speculated_step)
  score = base_model.generate_score(prompt)
  return score

def create_evaluation_prompt(cot_prefix, speculated_step):
  """評価プロンプトを作成する"""
  # CoTプレフィックスと投機されたステップを組み合わせたプロンプトを作成
  prompt = cot_prefix + speculated_step + "Utility score (0-9):"
  return prompt
```

# Training-free Guidance in Text-to-Video Generation via Multimodal Planning and Structured Noise Initialization

[View Paper](http://arxiv.org/abs/2504.08641v1)

## 1. 既存研究では何ができなかったのか

既存のText-to-Video (T2V) モデルは、生成される動画の品質は向上しているものの、以下の点で課題がありました。

*   **テキストの正確な追従の難しさ**: 特に、空間レイアウトやオブジェクトの軌道を正確に制御する必要があるプロンプトにおいて、テキストの指示に忠実な動画を生成することが困難でした。
*   **レイアウトガイダンス手法のメモリ消費**: 近年の研究では、レイアウトガイダンスを用いてT2Vモデルのテキストアラインメントを改善する試みがなされていますが、多くの場合、推論時にファインチューニングや attention map の操作を必要とし、メモリ消費量が大幅に増加していました。大規模なT2Vモデルをバックボーンとして採用することが困難になっていました。
*   **異なる T2V バックボーンへの適応**: レイアウトガイダンスのために T2V モデルをファインチューニングする必要がある場合、異なる T2V モデルに適用するには再トレーニングが必要となり、汎用性に欠けていました。
*   **オブジェクトの動的な状態変化やインタラクションの制御**: 既存の手法では、オブジェクトの状態変化やオブジェクト間のインタラクションを、バウンディングボックスだけで効果的に制御することが困難でした。

## 2. どのようなアプローチでそれを解決しようとしたか

本研究では、これらの課題を解決するために、"Video-MSG" というトレーニングフリーのガイダンス手法を提案しました。Video-MSGは、Multimodal planning と Structured noise initialization に基づいています。具体的なアプローチは以下の通りです。

1.  **Video Sketch の生成**: Video-MSGは、まずVideo Sketchと呼ばれる、最終的な動画のための詳細な時空間計画を作成します。これは、背景、前景、オブジェクトの軌道を指定する一連のドラフト動画フレームとして表現されます。Video Sketch の生成は、以下のステップで行われます。
    *   **背景の生成**: Multimodal LLM (MLLM) を用いて、与えられたテキストプロンプトから背景に関する詳細なテキスト記述を生成します。次に、Text-to-Image (T2I) モデルと Image-to-Video (I2V) モデルを用いて、背景画像と自然なアニメーションを生成します。
    *   **前景オブジェクトのレイアウトと軌道の計画**: MLLM とオブジェクト検出器を用いて、前景オブジェクトのレイアウトと軌道を計画します。MLLM は、背景画像内のオブジェクトのバウンディングボックス情報に基づいて、前景オブジェクトの適切な位置と動きを推論します。
2.  **構造化ノイズ初期化によるガイダンス**: 生成された Video Sketch を用いて、既存の T2V 拡散モデルをガイドします。このガイダンスは、ノイズ反転とノイズ除去のプロセスを通じて行われます。ノイズ反転比率をLLMによって動的に推定することで、テキストとレイアウトへの忠実性と、生成される動画の自然さを両立させます。

## 3. 結果、何が達成できたのか

Video-MSG は、以下の点で優れた成果を達成しました。

*   **テキストアラインメントの向上**: VideoCrafter2 や CogVideoX-5B などの複数の T2V バックボーンにおいて、テキストアラインメントを大幅に向上させました。
*   **ファインチューニング不要**: トレーニングフリーであるため、既存の T2V モデルをファインチューニングする必要がなく、さまざまな T2V バックボーンに容易に適用できます。
*   **メモリ効率**: 推論時に追加のメモリを必要とする attention map 操作を必要としないため、大規模な T2V モデルをバックボーンとして使用する際のメモリ制約を軽減できます。
*   **モーションバインディング、数量、空間関係の改善**: T2VCompBench および VBench の評価において、特にモーションバインディング、数量、空間関係といった側面で顕著な改善が見られました。CogVideoX-5B をバックボーンとして使用した場合、モーションバインディングが 52.46%、数量が 40.11%、空間関係が 11.15% 向上しました。

## 4. Limitationや問題点は何か

Video-MSG には、以下の Limitation や問題点が考えられます。

*   **動的な属性バインディングやオブジェクト間のインタラクションの制御**: 論文中では、動的な属性バインディング（オブジェクトの状態変化）やオブジェクト間のインタラクションを、バウンディングボックスのみで効果的に制御することは難しいと述べられています。
*   **MLLM の依存**: Video-MSG は MLLM に大きく依存しており、MLLM の性能が Video Sketch の品質に大きく影響します。MLLM が不正確な計画を立てた場合、最終的な動画の品質が低下する可能性があります。
*   **計算コスト**: Video Sketch の生成には、MLLM, T2I, I2V モデルなど、複数のモデルを使用するため、計算コストが高くなる可能性があります。
*   **Novel なオブジェクトやシーンへの対応**: Video-MSG は既存のモデル (T2I, I2V, Object Detection) を組み合わせることで実現されています。そのため、学習データに存在しないような Novel なオブジェクトやシーンの生成は難しい可能性があります。
*   **モーションの滑らかさとのトレードオフ**: ノイズ反転比率を低く設定することで、レイアウト制御を強化できますが、モーションの滑らかさが損なわれる可能性があります。適切なノイズ反転比率を自動的に推論する必要がある。

## 5. 技術的な詳細について

Video-MSG の主要な技術的要素は以下の通りです。

1.  **Video Sketch 生成**:
    *   **背景生成**: GPT-4o を使用して背景記述を生成し、T2I モデル (FLUX など) で背景画像を生成した後、I2V モデル (CogVideoX-5B など) でアニメーションを追加します。
    *   **前景オブジェクト**: GPT-4o は、背景画像内のオブジェクト検出によって得られたバウンディングボックス情報に基づいて、前景オブジェクトのレイアウトと軌道を計画します。
    *   **オブジェクト抽出**:前景オブジェクトの画像を生成する際、前景オブジェクトのみを抽出するために、Recognize-Anything (RAM) などのセグメンテーションモデルを使用します。
2.  **構造化ノイズ初期化**:
    *   **ノイズ反転**: 以下の式で表されるノイズ反転プロセスを用いて、Video Sketch の情報を T2V 拡散モデルに注入します。

    ```python
    # latent をVAEでエンコード
    z_0 = vae.encode(image_sequence)

    # ノイズを付加
    epsilon = torch.randn_like(z_0)
    z_t_inv = sqrt(alpha_t) * z_0 + sqrt(1 - alpha_t) * epsilon
    ```
    ここで、`alpha_t` はノイズスケジュールにおける係数であり、`t_inv` はノイズ反転のタイムステップです。
    *   **ノイズ除去**: DPM-Solver++ を使用して、ノイズ除去プロセスを高速化します。DPM-Solver++ の更新式は以下の通りです。
    ```python
    def F(z, t):
      beta_t = noise_schedule[t]
      g_t_squared = noise_strength[t]**2
      epsilon_theta = diffusion_model(z, t) # 拡散モデルによるノイズ予測
      return -0.5 * beta_t * z - g_t_squared * epsilon_theta

    z_t_minus_1 = z_t + lambda_1 * F(z_t, t) + lambda_2 * F(z_t + lambda_3 * F(z_t, t), t_m)
    ```
    ここで、`lambda_1`, `lambda_2`, `lambda_3` はステップサイズ係数、`t_m` は中間ステップを表します。
3.  **MLLMプロンプト**:
    *   論文のAppendixには、背景記述、前景オブジェクトのレイアウトと軌道、ノイズ反転比率を決定するために使用されるプロンプトテンプレートが記載されています。
    *   特にノイズ反転比率決定のプロンプトには、タスクの特性（正確な軌道制御が必要か、動的な変化が必要か）を考慮するように指示が組み込まれています。

# VLM-R1: A Stable and Generalizable R1-style Large Vision-Language Model

[View Paper](http://arxiv.org/abs/2504.07615v1)

## 1. 既存研究では何ができなかったのか

既存のVision-Language Models (VLMs) は、特定のvisual understandingタスクにおいて、専門的なvisionモデル（例：Grounding DINO）と比較して性能が劣る場合がありました。 特に、Referring Expression Comprehension (REC) や Open-Vocabulary Object Detection (OVD) などのタスクにおいて、VLMsは十分な性能を発揮できていませんでした。 また、既存研究の多くは、マルチモーダル数学タスクに焦点を当てており、reward engineeringやデータ選択の重要性に関する包括的な調査が不足していました。 さらに、既存のVision-Language reinforcement learningフレームワークは、データ定義、モデルのモジュール性、およびトレーニングのスケーラビリティにおいて柔軟性に欠けていました。

## 2. どのようなアプローチでそれを解決しようとしたか

本研究では、以下の主要なアプローチを用いて、VLMsのvisual reasoning能力を強化し、既存研究の課題を解決しようとしました。

1.  **VLM-R1フレームワークの開発**: DeepSeek R1の成功に触発され、Vision-LanguageドメインにR1スタイルの強化学習を適用するための、柔軟でスケーラブルなVLM-R1フレームワークを開発しました。 このフレームワークは、データ定義、モデルのモジュール性、およびトレーニングのスケーラビリティをサポートします。
2.  **GRPOアルゴリズムの採用**: DeepSeek R1によって採用されたGRPO（Group Relative Policy Optimization）アルゴリズムに焦点を当て、reward関数を柔軟に設計できるパイプラインを作成しました。
3.  **2つの代表的なVisual Understandingタスクの選択**: RECとOVDを選択し、RLがVLMsの性能向上にどのように貢献するかを調査しました。 これらのタスクは、bounding box出力形式を共有していますが、複雑さが異なるため、RLの効果を評価するのに適しています。
4.  **Reward Engineering**: OVDタスクにおけるreward hackingに対処するために、追加のペナルティ項を導入し、モデルが冗長な予測をしないように促しました。 具体的には、予測されたオブジェクトの数をground truthに近づけるために、`s_ovd * mAP`のreward関数を採用しました（`s_ovd = max(1, L_gt / L_pred)`）。
5.  **データ選択**: OVDタスクに対して、D
    データセットを選択しました。これは、COCOデータセットと比較して、より複雑なクエリが含まれているため、モデルの推論能力を向上させるのに役立ちます。
6.  **モデルのスケーリング**: 異なるサイズのモデル（3B, 7B, 32B）を使用して、RLがVLMsのパフォーマンスに与える影響を分析しました。

## 3. 結果、何が達成できたのか

本研究により、以下の成果が達成されました。

1.  **VLM-R1フレームワークの提供**: RLを用いたVLMsの性能向上を目的とした、柔軟で拡張可能なフレームワークを提供しました。
2.  **RLの有効性の実証**: RECおよびOVDタスクにおいて、RLがVLMsの性能を大幅に向上させることを示しました。 特に、out-of-domainデータセットでの一般化能力が向上しました。 例えば、RECタスクでは、3B RLモデルがLISA-Groundingで63.16のスコアを達成し、SFTモデルの54.82を上回りました。 OVDタスクでは、3B RLモデルがCOCOで21.1 APを達成し、SFTモデルの17.8を上回りました。
3.  **Reward Hackingの軽減**: OVDタスクにおけるreward hackingを特定し、それを軽減するためのreward engineering手法を開発しました。 具体的には、`s_ovd * mAP`のreward関数を導入することで、モデルが冗長な予測をすることを防ぎました。
4.  **データ選択の重要性の強調**: 複雑なクエリを含むデータセット（D
    ）を使用することで、VLMsの推論能力が向上することを示しました。
5.  **モデルのスケーリング効果の分析**: RLの効果はモデルサイズによって異なり、大規模モデルほど推論能力が向上することを示唆しました。
6. **OD aha momentの発見**: OVDタスクにおいて、モデルが最初にオブジェクトの存在を推論してからbounding boxを予測するという、新たな推論行動の出現を確認しました。

## 4. Limitationや問題点は何か

本研究には、以下のLimitationsや問題点があります。

1.  **GRPOアルゴリズムへの限定**: VLM-R1フレームワークは、現在のところGRPOアルゴリズムのみをサポートしています。 将来的には、他のRLアルゴリズムの統合が望まれます。
2.  **タスクの限定**: 実験はRECとOVDタスクに限定されています。 他のvisual understandingタスクにおけるVLM-R1の有効性を評価する必要があります。
3.  **Reward設計の複雑さ**: OVDタスクにおけるreward hackingの軽減には、慎重なreward設計が必要です。 一般的なreward設計手法の開発が求められます。
4.  **計算コスト**: RLのトレーニングには、SFTと比較して高い計算コストが必要です。 特に、大規模モデルのトレーニングには、多くのGPUリソースと時間が必要です。
5.  **データセットへの依存**: モデルの性能は、トレーニングに使用するデータセットの品質に大きく依存します。 データセットのバイアスが、モデルの一般化能力に影響を与える可能性があります。

**追加の考察**:

*   本研究で発見されたOD aha momentは、特定のタスクやreward設計に依存する可能性があります。 より普遍的な推論行動を促進するための研究が必要です。
*   VLM-R1フレームワークの汎用性を高めるために、さまざまなVLMアーキテクチャとの互換性を向上させる必要があります。
*   reward hackingを防止するための自動的なreward設計手法の開発が望まれます。

## 5. 技術的な詳細について

VLM-R1は、VLMsを強化学習によって改善するためのフレームワークです。 既存のOpen-R1をベースにしており、Vision-Languageドメインに拡張されています。

**フレームワークの構成要素**:

1.  **grpo_jsonl.py**:
    *   カスタムreward関数を定義し、タスクに合わせたトレーニングデータを準備します。
    *   VLM Module Definitionを通じて、さまざまなVLMsをサポートします。
2.  **grpo_trainer.py**:
    *   GRPOトレーニングプロセスを管理します。
    *   モデルの初期化、トレーニングパラメータの確認を行います。
    *   LoRA fine-tuning、vision tower freezing training、full parameters trainingをサポートします。
    *   モデルが複数のシーケンスを生成し、定義されたreward関数を使用してスコアリングします。
    *   rewardシグナルを使用して、GRPO損失を計算し、パラメータを最適化します。

**VLM Module**:

さまざまなVLMsをトレーニングプロセスに統合するために、VLM Moduleを設計しました。 このモジュールは、モデルのクラス名の取得や、入力質問をモデル固有のチャットテンプレートにフォーマットするなど、一般的なVLM機能をカプセル化します。

**GRPOアルゴリズム**:

PPOのような追加のcriticモデルを必要とするRLアルゴリズムとは異なり、GRPOは候補応答のグループを直接比較します。

**疑似コード**:

```python
def calculate_advantage(rewards):
  """
  Calculate advantage using GRPO.
  Args:
    rewards: A list of rewards for each candidate response.
  Returns:
    A list of advantages for each candidate response.
  """
  mean_reward = sum(rewards) / len(rewards)
  std_reward = (sum([(r - mean_reward)**2 for r in rewards]) / len(rewards))**0.5
  advantages = [(r - mean_reward) / std_reward for r in rewards]
  return advantages

def grpo_loss(policy, ref_policy, questions, responses, advantages, beta, epsilon):
  """
  Calculate GRPO loss.
  Args:
    policy: The current policy.
    ref_policy: The reference policy.
    questions: A list of questions.
    responses: A list of responses.
    advantages: A list of advantages for each response.
    beta: KL divergence ratio.
    epsilon: Clipping parameter.
  Returns:
    The GRPO loss.
  """
  loss = 0.0
  for i in range(len(responses)):
    prob_ratio = policy.prob(responses[i], questions[i]) / ref_policy.prob(responses[i], questions[i])
    s1 = prob_ratio
    s2 = clip(prob_ratio, 1 - epsilon, 1 + epsilon)
    min_val = min(s1 * advantages[i], s2 * advantages[i])
    kl_div = kl_divergence(policy, ref_policy, questions[i])
    loss += min_val - beta * kl_div
  return -loss / len(responses)

def clip(x, lower, upper):
  """
  Clip the value x between lower and upper.
  Args:
    x: The value to clip.
    lower: The lower bound.
    upper: The upper bound.
  Returns:
    The clipped value.
  """
  return max(lower, min(x, upper))

def kl_divergence(policy, ref_policy, question):
  """
  Calculate KL divergence between two policies.
  Args:
    policy: The current policy.
    ref_policy: The reference policy.
    question: The input question.
  Returns:
    The KL divergence.
  """
  # Simplified calculation for demonstration purposes
  return cross_entropy(policy.prob(question), ref_policy.prob(question))
```

**Reward関数**:

*   **REC**:
    *   Accuracy reward: `IoU(b*, f_rec(o))` (IoU: Intersection over Union, b*: ground truth bounding box, f_rec(o): bounding box extracted from the output sentence)
    *   Format reward: JSON形式のレスポンスをチェックします。
*   **OVD**:
    *   Accuracy reward: `s_ovd * mAP(b_pred, b_gt)` (s_ovd: penalty factor for redundant predictions, mAP: mean Average Precision, b_pred: predicted bounding boxes and class labels, b_gt: ground truth bounding boxes and class labels)
    *   Format reward: MarkdownスタイルのJSONレスポンスをチェックします。
