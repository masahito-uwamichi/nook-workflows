
# Phi-4-Mini-Reasoning: Exploring the Limits of Small Reasoning Language Models in Math

[View Paper](http://arxiv.org/abs/2504.21233v1)

## 1. 既存研究では何ができなかったのか

既存研究、特にDeepseek-R1などの研究は、LLMを用いて生成した合成データでSLMの推論能力を向上させることを示しましたが、具体的なモデリングレシピは公開されていませんでした。また、既存研究では、SLMの限られたモデル容量を考慮した系統的なトレーニングパラダイムが十分に探求されていませんでした。例えば、単に少量の高品質データでdistillationを行うと、かえって性能が低下する現象が観測されています。

## 2. どのようなアプローチでそれを解決しようとしたか

提案手法では、SLMのために特別に設計された4段階のトレーニングレシピを採用しています。

1.  **大規模なmid-training**: Deepseek-R1で生成された多様なlong-CoTデータを用いて、SLMに推論能力の基礎を埋め込みます。不正解の回答をrejection samplingで除外します。
2.  **教師ありfine-tuning (SFT)**: 高品質なlong-CoTデータでモデルをfine-tuningし、汎化能力を向上させます。mid-trainingデータセットから、よりコンパクトで代表的なサブセットを選択します。
3.  **Rollout DPO**: LLMによって生成された不正解のサンプルを再利用し、preference datasetを作成してRollout DPOを行います。これにより、モデルのアライメントと推論能力を改善します。
4.  **Reinforcement Learning (RL) with Verifiable Reward**: 最終的な回答の正しさに基づいて、検証可能な報酬を用いたRLでモデルをfine-tuningします。

さらに、トレーニングの安定性を確保するために、プロンプト最適化、報酬の再調整（オーバーサンプリングとフィルタリング）、温度アニーリングなどの改善策を導入しています。

## 3. 結果、何が達成できたのか

3.8BパラメータのPhi-4-MiniをベースにしたPhi-4-Mini-Reasoningモデルは、数学的推論タスクにおいて、DeepSeek-R1-Distill-Qwen-7Bを3.2ポイント、DeepSeek-R1-Distill-Llama-8Bを7.7ポイント上回るなど、より大規模な推論モデルを凌駕しました。Math-500においては、DeepSeek-R1-Distill-Qwen-7Bを上回る性能を達成しています。これらの結果は、大規模で高品質なCoTデータを用いた慎重に設計されたトレーニングレシピが、リソース制約のある小型モデルでも強力な推論能力を引き出すのに効果的であることを検証しています。

## 4. Limitationや問題点は何か

*   **データ依存性**: モデルの性能は、CoTデータの品質と多様性に大きく依存します。特に、mid-trainingで使用するデータの質が重要であると考えられます。
*   **タスク依存性**: 現在の評価は主に数学的推論タスクに焦点を当てています。他の種類の推論タスク（例えば、常識推論や論理推論）における性能は不明です。
*   **汎化性能**: fine-tuningデータセットが特定のドメインに偏っている場合、モデルの汎化性能が制限される可能性があります。
*   **RLの安定性**: SLMのRLトレーニングは、LLMと比較して不安定になる傾向があります。特に、報酬のばらつきや応答長の不均一性などが問題を引き起こす可能性があります。
*   **安全性の問題**: Phi-4-Mini-Reasoningは安全性を考慮して開発されていますが、有害なコンテンツ、直接的なjailbreak、モデルのgroundednessに関する潜在的な安全上のリスクが残る可能性があります。
*   **計算コスト**: トレーニングには多大な計算資源が必要です。特に、大規模なmid-trainingとRL段階は、リソース集約的です。

## 5. 技術的な詳細について

提案手法は、以下のコンポーネントで構成されます。

*   **Distillation as Mid-training:**
    *   Base model: Phi-4-Mini (3.8B parameters)
    *   Dataset: LLM-generated CoT data (多様なドメイン、様々な難易度)
    *   Sampling: DeepSeek-R1によるサンプリング、不正解をrejection samplingで除去
    *   Objective: Causal language modeling (next token prediction)
    *   Packing: Multi-example packing
*   **Supervised Fine-Tuning (SFT):**
    *   Dataset: Mid-trainingデータセットから選択されたコンパクトで代表的なサブセット
    *   Quality: College levelを超える難易度の多様な数学ドメインを網羅
    *   Mode: Fine-tuning to decide when to stop generating
*   **Rollout DPO:**
    *   Objective: Direct Preference Optimization (DPO)
    *   Preference dataset: 正解をpreferred rollout、不正解をdis-preferred rolloutとして作成
    *   Data Quality: high-schoolレベル以上の数学問題を使用
    ```python
    def dpo_loss(pi_theta, pi_ref, x, y_w, y_l, beta):
        """
        DPO loss function.

        Args:
            pi_theta: Policy to be optimized.
            pi_ref: Reference policy.
            x: Input sequence.
            y_w: Preferred rollout.
            y_l: Dispreferred rollout.
            beta: Temperature parameter.

        Returns:
            DPO loss.
        """
        log_sigma = log(sigmoid(beta * (log(pi_theta(y_w | x) / pi_ref(y_w | x))) - beta * (log(pi_theta(y_l | x) / pi_ref(y_l | x)))))
        return -log_sigma
    ```
*   **Reinforcement Learning with Verifiable Reward (RLVR):**
    *   Algorithms: PPO, GRPO
    *   Reward: 最終的な回答の正しさに基づく報酬 (verify()関数で検証)
    ```python
    def reward(y_hat, y):
        """
        Verifiable reward function.

        Args:
            y_hat: Model's final answer.
            y: Ground truth answer.

        Returns:
            Reward (+1 for correct, -1 for incorrect).
        """
        if verify(y_hat, y):
            return 1
        else:
            return -1
    ```
    *   GRPOにおける問題点:
        *   グループ内での応答長 variability
        *   一様な報酬下での vanishing gradients
        *   不十分な exploration
    *   改善策:
        *   均一なトークン長を持つプロンプトのみを選択
        *   正の報酬の応答を保持し、負の報酬の応答を同じ数だけサンプリング
        *   グループレベルの精度が一定のしきい値を超えるプロンプトをフィルタリングアウト
        *   温度アニーリング (初期温度1.0から線形に0.6まで減衰)

# Sadeed: Advancing Arabic Diacritization Through Small Language Model

[View Paper](http://arxiv.org/abs/2504.21635v1)

## 1. 既存研究では何ができなかったのか

既存の研究は、アラビア語のダイアクリティカル（diacritization: 母音や発音区別符号の付与）において、以下の点で限界がありました。

*   **データ不足:** 高品質なラベル付きデータが不足しており、特に現代標準アラビア語（MSA）のデータが不足していました。古典アラビア語（CA）に偏ったデータセットが多く、MSAへの適用が困難でした。
*   **文脈依存性の考慮不足:** ダイアクリティカルは文脈によって変化するため、文全体の文脈を理解する必要がありましたが、既存モデルでは十分に考慮されていませんでした。
*   **ベンチマークの限界:** 既存のベンチマークはCAまたはMSAに偏っており、多様なテキストジャンルを網羅していませんでした。データ分割やラベルにエラーが含まれているものもありました。
*   **ベンチマークの汚染:** 既存のデータセット（Fadel, Abbad）間でのデータの重複が大きく、モデルの評価の信頼性を損なっていました。
*   **Punctuationの扱い:** 句読点がダイアクリティカルの曖昧さを引き起こす可能性があるにも関わらず、考慮されていませんでした。
*   **モデルのHallucination:** モデルが出力時に余分な単語を追加したり、単語を修正したりすることがあり、正確なダイアクリティカルを生成する妨げになっていました。

## 2. どのようなアプローチでそれを解決しようとしたか

これらの課題を解決するために、本研究では以下のアプローチを採用しました。

*   **Sadeedの開発:** Kuwain 1.5Bをベースとした、decoder-onlyのsmall language model（SLM）であるSadeedをfine-tuningしました。Sadeedは、高品質でノイズのないダイアクリティカルテキストで学習しました。
*   **高品質なデータセットの構築:** 厳密なデータクリーニングと正規化パイプラインを通じて、高品質なダイアクリティカルデータセットを構築しました。このパイプラインには、テキストの正規化、ダイアクリティカルエラーの修正、アラビア語テキストの標準化が含まれます。特に、 Sukunの扱いや、Iltiqa’ as-sākinaynの問題を解決することに注力しました。
*   **SadeedDiac-25の導入:** CAとMSAの両方を含む、新しいベンチマークSadeedDiac-25を導入しました。このベンチマークは専門家によって精査され、以前のベンチマークの欠点を回避するように設計されています。テキストは様々なドメインから収集され、言語的、トピック的な多様性を確保しています。
*   **ベンチマークの分析:** 既存のベンチマーク（Fadel, Abbad, CATT）を詳細に分析し、データ分割、ラベル、内容のエラーを特定しました。
*   **Question-Answering形式でのFine-tuning:** ダイアクリティカルのタスクをQuestion-Answeringタスクとして再構築することで、モデルの学習をより効率的にしました。
*   **Inference時の工夫:** Hallucinationを修正するために、Needleman-Wunschアルゴリズムを使用しました。入力と出力を比較し、追加された単語を削除、欠落した単語を復元、変更された単語を元のダイアクリティカルなしのバージョンに置き換えることで、出力の精度を高めました。

## 3. 結果、何が達成できたのか

本研究により、以下の成果が得られました。

*   **Sadeedの性能:** Sadeedは、小規模な計算リソースを使用しているにもかかわらず、大規模言語モデルに匹敵する性能を達成し、類似ドメインで訓練された従来のモデルを上回りました。
*   **ベンチマークの改善:** SadeedDiac-25は、より公平で包括的な評価を可能にし、多様なテキストジャンルと複雑さのレベルを網羅しています。
*   **データセットの公開:** 高品質なデータセットを公開し、アラビア語ダイアクリティカルの研究開発を支援します。
*   **SOTAの達成:** Fadelデータセットにおいて、WERとDERにおいてSOTAを達成しました。
*   **hallucinationの削減:** Needleman-Wunschアルゴリズムを使用したInference時の修正により、hallucinationを効果的に削減し、出力の精度を高めました。

## 4. Limitationや問題点は何か

本研究には、以下の制限事項と問題点があります。

*   **モデルのHallucination:** Sadeedはhallucinationを起こしやすく、特に非アラビア語の単語で顕著です。この問題に対処するためには、制約付きデコーディングなどの高度な技術が必要です。
*   **計算リソースの制限:** 計算リソースの制約により、パラメータを増やすことや、高品質なデータでの長期的なトレーニングが制限されました。これにより、モデルの性能が潜在的に制限されています。
*   **MSAデータの不足:** 現代標準アラビア語（MSA）の高品質なダイアクリティカルデータセットの入手可能性が限られています。これにより、異なるジャンルや実際のMSAアプリケーションで汎化できるモデルの開発が困難になっています。
*   **汎化性能:** SadeedはFadelデータセットでは高い性能を発揮しますが、SadeedDiac-25ベンチマークでは性能が低下します。これは、SadeedがMSAデータでのトレーニングが限られているため、MSAコンテンツに対する汎化性能が低いことが原因と考えられます。
*   **ベンチマークの完全性:** SadeedDiac-25は既存のベンチマークより改善されていますが、完全に網羅的であるとは限りません。特定のドメインやスタイルが過小評価されている可能性があります。
*   **小規模モデルの限界:** Sadeedは比較的小規模なモデルであるため、より大規模なモデルと比較して、文脈を完全に理解し、複雑な言語構造を捉える能力に限界がある可能性があります。

## 5. 技術的な詳細について

Sadeedはdecoder-onlyのsmall language modelであり、Kuwain 1.5Bをベースにしています。ダイアクリティカルタスクをQuestion-Answeringタスクとして再構築し、fine-tuningを行っています。以下に技術的な詳細を示します。

*   **ベースモデル:** Kuwain 1.5B (Hennara et al., 2025)
*   **アーキテクチャ:** Decoder-only Transformer
*   **データセット:** Tashkeela corpus, Arabic Treebank (ATB)をクリーニング・正規化
*   **データ前処理:**
    *   テキストの正規化
    *   ダイアクリティカルエラーの修正
    *   Sukunの扱い (elongation letters, definite article lām)
    *   Iltiqa’ as-sākinaynの解決
    *   50-60 wordsのチャンクに分割 (hierarchical approach)
*   **Fine-tuning:**
    *   ダイアクリティカルタスクをQuestion-Answeringタスクとして再構築
    *   `Template transformation`:  入力テキストをテンプレートに変換し、モデルに入力
*   **Inference:**
    *   Needleman-Wunschアルゴリズムを使用してhallucinationを修正
    *   入出力の比較による単語の修正

**疑似コード (Needleman-Wunschアルゴリズム)**

```python
def needleman_wunsch(seq1, seq2):
    # Initialization
    n = len(seq1)
    m = len(seq2)
    score = [[0 for _ in range(m + 1)] for _ in range(n + 1)]

    # Gap penalty
    gap = -1

    # Fill the matrix
    for i in range(n + 1):
        score[i][0] = i * gap
    for j in range(m + 1):
        score[0][j] = j * gap

    # Calculate scores
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            match = score[i-1][j-1] + (1 if seq1[i-1] == seq2[j-1] else -1)
            delete = score[i-1][j] + gap
            insert = score[i][j-1] + gap
            score[i][j] = max(match, delete, insert)

    # Traceback
    align1 = ""
    align2 = ""
    i = n
    j = m
    while i > 0 or j > 0:
        if i > 0 and j > 0 and score[i][j] == score[i-1][j-1] + (1 if seq1[i-1] == seq2[j-1] else -1):
            align1 = seq1[i-1] + align1
            align2 = seq2[j-1] + align2
            i -= 1
            j -= 1
        elif i > 0 and score[i][j] == score[i-1][j] + gap:
            align1 = seq1[i-1] + align1
            align2 = "-" + align2
            i -= 1
        else:
            align1 = "-" + align1
            align2 = seq2[j-1] + align2
            j -= 1

    return align1, align2
```

## 5. 技術的な詳細について

LLM推論の最適化は、モデルのパラメータ数、アテンションメカニズムの計算量、KVキャッシュのメモリ管理など、多くの課題があります。以下に、主要な技術要素を説明します。

*   **モデル並列化:**
    *   **パイプライン並列化:** モデルのレイヤーを複数のデバイスに分散し、各デバイスが異なるレイヤーを処理することで並列化します。
        ```python
        # 各GPUが担当するレイヤー
        gpu1_layers = [layer1, layer2, layer3]
        gpu2_layers = [layer4, layer5, layer6]
        # 各GPUで順にレイヤーを処理
        output_gpu1 = process_layers(gpu1_layers, input_data)
        output_gpu2 = process_layers(gpu2_layers, output_gpu1)
        ```
    *   **テンソル並列化:** 個々のレイヤー（特に巨大な行列演算）を分割し、複数のデバイスで並列に計算します。
        ```python
        # 行列AをGPUごとに分割
        gpu1_A = A[:, :A.shape[1]//2]
        gpu2_A = A[:, A.shape[1]//2:]
        # 分割された行列で並列に計算
        gpu1_output = gpu1_A @ B
        gpu2_output = gpu2_A @ B
        # 結果を結合
        output = concat(gpu1_output, gpu2_output)
        ```
*   **リクエストスケジューリング:**
    *   **Inter-request scheduling:** 複数のリクエストを処理する順序を最適化します。例えば、短いリクエストを優先してレイテンシを削減します。
        ```python
        requests = [request1, request2, request3]
        # リクエストの長さを予測
        request_lengths = [predict_length(req) for req in requests]
        # 長さでソート
        sorted_requests = sort_by_length(requests, request_lengths)
        # 短い順に処理
        for req in sorted_requests:
            process_request(req)
        ```
    *   **Intra-request scheduling:** 個々のリクエストを細かく分割し、並列処理を最大化します。
*   **KVキャッシュの最適化:**
    *   **PagedAttention:** OSのページングの概念を導入し、KVキャッシュを固定サイズのページに分割して管理することで、メモリの断片化を解消します。
        ```python
        kv_cache = PagedKVCache(page_size=4096)
        # KVキャッシュにデータを格納
        kv_cache.store(key, value)
        ```
    *   **圧縮:** KVキャッシュを量子化したり、冗長な情報を削除したりすることで、メモリ使用量を削減します。
*   **Prefill/Decode分離:** PrefillフェーズとDecodeフェーズを異なる環境で実行し、各フェーズに特化した最適化を適用します。
    ```python
    # Prefillフェーズ
    prefill_output = prefill(input_data)
    # Decodeフェーズ
    decoded_output = decode(prefill_output)
    ```

# Softpick: No Attention Sink, No Massive Activations with Rectified Softmax

[View Paper](http://arxiv.org/abs/2504.20966v1)

## 1. 既存研究では何ができなかったのか

既存研究では、TransformerのAttention機構におけるSoftmax関数のいくつかの課題を完全に解決することができていませんでした。

*   **Attention Sink:** Softmaxは確率分布を生成するため、特定のトークン（特に文頭のBOSトークン）に過剰な注意を割り当てる「Attention Sink」と呼ばれる現象が発生します。これは、モデルが意味的に重要でないトークンに過度に依存する原因となります。
*   **Massive Activations:** Softmaxの使用は、Transformerの隠れ層において極端に大きな活性化値（Massive Activations）を生じさせます。これは、量子化や低精度学習において問題となり、モデルの圧縮や高速化を妨げます。
*   **量子化性能の低下:** Massive Activationは量子化の精度を低下させます。
*   **Attention Sinkの完全な除去:** 既存研究では、Attention Sinkを緩和する試みはあったものの、完全には除去できていませんでした。例えば、正規化なしのSigmoid AttentionやAttention Biasの追加などが試みられましたが、追加パラメータが必要であったり、深い層で効果が薄れたりするなどの問題がありました。

## 2. どのようなアプローチでそれを解決しようとしたか

この論文では、「Softpick」という新しい活性化関数を提案し、Softmaxの代替として使用することで、上記の課題を解決しようと試みました。Softpickは、Softmaxの特性を維持しつつ、Attention SinkとMassive Activationsを抑制するように設計されています。Softpickの主な特徴は以下の通りです。

*   **Rectified Linear Unit (ReLU) の利用:** Softmaxの指数関数にReLUを適用することで、負の入力に対する出力をゼロにし、スパースなAttentionマップを生成します。これにより、不要な値の蓄積を最小限に抑え、Attention Sinkを防ぎます。

    ```python
    def softpick(x):
        exp_x = [math.exp(xi) for xi in x]
        numerator = [max(exp_xi - 1, 0) for exp_xi in exp_x]
        denominator = sum(abs(exp_xi - 1) for exp_xi in exp_x)
        
        # add epsilon to prevent division by zero
        epsilon = 1e-5
        
        return [num / (denominator + epsilon) for num in numerator]
    ```

*   **絶対値関数の利用:** Softmaxの分母の計算において、ReLU適用後の値の絶対値を使用します。これにより、負の入力も分母に貢献し、勾配の流れを維持します。これにより、Attention Sinkを防ぎつつ、Softmaxのヤコビ行列の性質を維持します。

## 3. 結果、何が達成できたのか

SoftpickをTransformerのAttention機構に適用した結果、以下の成果が得られました。

*   **Attention Sinkの除去:** Softpickを使用することで、Attention Sinkを完全に除去することができました。実験では、Sink Rateが0%となり、モデルが意味的に重要なトークンに適切に注意を払うことが確認されました。
*   **Massive Activationsの抑制:** Softpickは、隠れ層におけるMassive Activationsを大幅に抑制しました。活性化値の尖度（Kurtosis）が大幅に減少し、量子化や低精度学習に適したモデルを生成することができました。
*   **量子化性能の向上:** Softpickを使用したモデルは、量子化後の性能がSoftmaxを使用したモデルよりも一貫して優れていました。特に、低ビット精度での量子化において、その効果が顕著でした。
*   **同等の性能:** ベンチマークテストにおいて、Softpickを使用したモデルは、Softmaxを使用したモデルと同等以上の性能を発揮しました。

## 4. Limitationや問題点は何か

Softpickにはいくつかの制限と問題点があります。

*   **Underscoring:** 長い文脈を持つテキストを処理する際、SoftpickはAttentionスコアを過小評価する傾向があります。分母の計算に絶対値関数を使用しているため、負のスコアを持つトークンが多い場合、正のスコアを持つトークンの重要性が相対的に低下します。
*   **Passkey Retrievalタスクの性能:** SoftpickはPasskey Retrievalタスクにおいて、Softmaxよりも性能が低い結果となりました。スコアが過小評価されることによる、Valueの信号の弱まりが原因として考えられます。
*   **モデルのスケールアップ:** 現時点では、340Mパラメータのモデルでのみ実験が行われています。より大規模なモデル（2B、7Bパラメータ）での検証が必要です。
*   **長期的な学習:** Rectified-Only Softmaxにおいて、長期間学習させるとベースラインのSoftmaxから乖離していくという実験結果が得られています。SoftpickはRectified-Only Softmaxの欠点を補うように設計されていますが、Softpickにおいても長期的な学習における安定性を確認する必要があります。

## 5. 技術的な詳細について

Softpickは、Softmax関数を以下の様に変更することでAttention SinkとMassive Activationを軽減します。

1.  **ReLUの適用:** まず、Softmaxの指数関数の出力から1を引き、ReLU関数を適用します。これにより、負の入力に対する出力はゼロとなり、Attentionマップのスパース性が向上します。
2.  **分母の修正:** Softmaxの分母の計算において、ReLU適用後の値の絶対値を使用します。これにより、負の入力も勾配の計算に影響を与え、学習の安定性を維持します。

Softpickのヤコビ行列は以下のようになります。

```
def jacobian_softpick(x, i, j):
  """
  Softpick関数のヤコビ行列の要素を計算する

  引数:
  x: 入力ベクトル (リスト)
  i: 出力インデックス
  j: 入力インデックス

  戻り値:
  ヤコビ行列の要素の値
  """

  exp_x = [math.exp(xi) for xi in x]
  numerator = [max(exp_xi - 1, 0) for exp_xi in exp_x]
  denominator = sum(abs(exp_xi - 1) for exp_xi in exp_x)
  epsilon = 1e-5 # add epsilon to prevent division by zero
  denominator_safe = denominator + epsilon

  softpick_i = numerator[i] / denominator_safe
  
  def step(x):
    return 1 if x > 0 else 0
  
  def sign(x):
    return 1 if x > 0 else -1 if x < 0 else 0
  
  if i == j:
    return step(x[i]) * (exp_x[i] / denominator_safe) - sign(x[j]) * (exp_x[j] / denominator_safe) * softpick_i
  else:
    return -sign(x[j]) * (exp_x[j] / denominator_safe) * softpick_i
```

FlashAttention-2との互換性も考慮されており、オンライン単一パス計算が可能になっています。論文のAppendixには、FlashAttention-2のForward PassとBackward PassのアルゴリズムがSoftpick用に修正されたものが掲載されています。

# COMPACT: COMPositional Atomic-to-Complex Visual Capability Tuning

[View Paper](http://arxiv.org/abs/2504.21850v1)

## 1. 既存研究では何ができなかったのか

既存のMultimodal Large Language Models (MLLMs) は、単純な視覚言語タスクでは優れた性能を発揮しますが、複数の能力を必要とする複雑なタスク、例えば、オブジェクトの認識、それらのカウント、空間的関係の理解などを同時に行う必要がある場合に苦戦します。これは、Visual Instruction Tuning (VIT) がデータ量のスケーリングに重点を置いており、トレーニング例の構成的複雑さを考慮していなかったことが部分的な原因です。具体的には、既存のVITデータセットは、単一の能力を必要とする単純なクエリが大部分を占めており、複数の能力を組み合わせる必要のある複雑なタスクに対するモデルの汎化能力が不足していました。既存研究では、compositionalityを規模の副産物として扱っており、学習可能な能力として捉えていませんでした。
## 2. どのようなアプローチでそれを解決しようとしたか

本論文では、COMPACT (COMPositional Atomic-to-complex visual Capability Tuning) という、トレーニング例の構成的複雑さを明示的に制御するトレーニングデータセットを生成するアプローチを提案しています。具体的には、以下の手順でデータセットを構築します。

1.  **原子能力の定義:** 色、オブジェクト認識、空間関係など、複雑な視覚タスクの基礎となる10個の原子能力を定義します。
2.  **組み合わせの生成:** これらの原子能力を組み合わせて、さまざまな複雑さを持つ質問を生成します。質問の複雑さは、質問を解決するために必要な原子能力の数で定義します。例えば、「赤いボールはどこにありますか？」という質問は、色と空間関係の2つの原子能力を必要とします。
3.  **質問の生成:** Gemini-2.0-Flashを使用して、指定された原子能力の組み合わせを自然に統合する質問と回答のペアを生成します。プロンプトには、質問が視覚情報から答えられる必要があり、簡潔であること、指定された能力を自然に統合することなどの制約が含まれています。
4.  **検証:** 生成された質問の品質と、要求される原子能力が実際に必要とされているかを検証します。不適切な質問はフィルタリングされます。
5.  **データセットの混合:** 生成された構成的チューニングデータと、既存のVITデータセットの小規模なサブセットを組み合わせて、最終的なトレーニングデータセットを作成します。VITサブセットは、モデルの指示追従能力を維持するために使用されます。
## 3. 結果、何が達成できたのか

COMPACTを使用することで、MLLMは原子能力の組み合わせでトレーニングし、より効率的に複雑な能力を学習できるようになりました。実験結果は以下の通りです。

*   全ベンチマークにおいて、LLaVA-665k VITと同等の性能を、10%未満のデータで達成しました。
*   特に、MMStarで83.3%、MM-Vetで94.0%という大幅な改善を達成しました。これは、4つ以上の原子能力を必要とする特に複雑な質問において顕著です。
*   従来のVITデータ(LLaVA)のcomplexity distributionでは90.1%の質問が2つ以下の能力を必要としていたのに対し、COMPACTでは異なるレベルの構成的複雑さ全体でバランスの取れた分布を強制的に実現しました。

COMPACTは、データ効率の高い、スケーラブルな視覚的構成的チューニングレシピを提供し、複雑な視覚言語タスクの改善に貢献します。
## 4. Limitationや問題点は何か。本文で言及されているものの他、あなたが考えるものも含めて

論文で言及されている制限事項：

*   **データ生成の依存性:** データ生成にクローズドソースのモデル（Gemini）を使用しているため、Geminiの持つ構成的制限やバイアスがデータセットに導入される可能性があります。
*   **データ生成コスト:** データ生成プロセスが高価であり、再現性に課題が残る可能性があります。
*   **知識集約型タスクへの適用:** 視覚中心の能力の構成に焦点を当てているため、視覚的推論の範囲外にある知識集約型タスクには最適ではない可能性があります。論文内でも、知識集約的なタスクでは性能改善が小さいことが報告されています。
*   **高次の構成的複雑さへの対応:** 現在のデータレシピでは、複雑さk=3までのデータしか生成されていません。高次の構成的複雑さを持つデータ生成は、クローズドソースモデルの信頼性が低下するため困難です。

私が考える制限事項：

*   **原子能力の定義の恣意性:** 原子能力の定義は、研究者の判断に依存する部分があり、異なる定義を採用した場合に結果がどのように変化するかは不明です。より網羅的な原子能力の体系が必要になる可能性があります。
*   **検証プロセスの信頼性:** Gemini-2.0-Flashによる質問の検証プロセスも、モデル自身の能力に依存するため、完璧ではありません。誤った質問がデータセットに含まれる可能性や、適切な質問が誤って除外される可能性があります。
*   **データセットの多様性:** COMPACTデータセットは、特定の生成プロセスによって作成されるため、現実世界の視覚データの多様性を十分に捉えられていない可能性があります。
*   **指示追従能力のトレードオフ:** 構成的チューニングに重点を置くことで、指示追従能力が低下する可能性があります。VITサブセットのサイズを大きくすると指示追従能力は向上しますが、構成的チューニングの効果が薄れる可能性があります。
*   **評価ベンチマークの偏り:** 論文で評価に使用されているベンチマークは、特定の種類の視覚タスクに偏っている可能性があります。より多様なベンチマークでの評価が必要です。

## 5. 技術的な詳細について。技術者が読むことを想定したトーンで

COMPACTの核となるのは、原子能力を組み合わせた質問を生成し、それに基づいてMLLMをファインチューニングするプロセスです。以下に詳細を記載します。

1.  **原子能力の定義:**
    *   `ATTRIBUTION`: 色 (color)、形状 (shape)
    *   `RECOGNITION`: オブジェクト認識 (object recognition)、アクション認識 (action recognition)、テキスト認識 (text recognition)、空間認識 (spatial recognition)、カウント (counting)
    *   `RELATION`: 空間関係 (spatial relationship)、オブジェクトインタラクション (object interaction)、シーン理解 (scene understanding)

2.  **データ生成パイプライン:**
    *   **入力:** VITデータセットからランダムにサンプリングされた画像。
    *   **能力サンプリング:** 10個の原子能力の集合から、`k`個の能力をランダムにサンプリング。同じ画像に対して、能力の組み合わせが重複しないように工夫。また、まだ選択されていない能力を優先する。
    *   **質問生成:** Gemini-2.0-Flashにプロンプトを与え、`k`個の能力を自然に統合した質問と回答のペアを生成させる。
        *   プロンプトの制約:
            *   質問は視覚情報が必要。
            *   回答は簡潔。
            *   `k`個の能力を自然に統合 (andやカンマで分離しない)。
            *   画像に実際に存在するオブジェクトや特徴を参照。
        *   出力形式: JSON (`question`, `answer`, `required_capabilities`, `confidence_score`)
    *   **検証:** Gemini-2.0-Flashを用いて、生成された質問の品質と能力の要件を検証。
        *   品質フィルタリング: 回答がinformativeでない場合、confidence_scoreが70未満の場合、または既存の質問と60%以上の単語を共有する場合は除外。

# ReVision: High-Quality, Low-Cost Video Generation with Explicit 3D Physics Modeling for Complex Motion and Interaction

[View Paper](http://arxiv.org/abs/2504.21855v1)

## 1. 既存研究では何ができなかったのか

既存のビデオ生成モデルは、以下の点で課題を残していました。

*   **複雑なモーションとインタラクションの生成の難しさ:** 現状のモデルでは、物理法則に基づいたリアルなモーション、特に複雑な動きやオブジェクト間のインタラクションを伴うビデオを生成することが困難でした。例えば、複数のキャラクターが同時に動き、互いに影響し合うような状況を正確に表現することが苦手でした。
*   **細かいモーション制御の不足:** モデルのスケールアップやデータセットの質の向上だけでは、物理世界の複雑さを完全に捉えることが難しく、生成されるビデオのモーションを細かく制御することが困難でした。例えば、キャラクターの特定部位（手や腕など）の動きを正確に指示することが難しい状況でした。
*   **モーションの物理的な妥当性の欠如:** 現状のモデルでは、生成されたビデオが物理的な制約に従っていないことが多く、不自然な動きやオブジェクトのインタラクションが発生していました。
*   **人間のアニメーション技術の適用制限:** 人間のイメージアニメーションモデルは、事前に定義された2Dキーポイントの軌跡に従うことで、複雑なモーションを持つ一貫性のある正確なビデオ出力を実現していましたが、一般的なビデオ生成タスクでは、このような強いガイダンス信号が利用できないため、直接適用することが困難でした。
*   **暗黙的な運動情報の活用不足:** 生成されたビデオに埋め込まれている暗黙的な運動情報をガイダンスとして活用し、ビデオの品質をさらに向上させるためのフレームワークが不足していました。

## 2. どのようなアプローチでそれを解決しようとしたか

ReVision は、これらの課題を解決するために、以下の3段階のアプローチを採用しました。

**段階1: 粗いビデオの生成**

*   まず、Stable Video Diffusion (SVD)のようなビデオ拡散モデルを使用して、テキストや初期フレームなどの条件に基づいて粗いビデオを生成します。

**段階2: 3Dモーションシーケンスの抽出と洗練**

*   次に、粗いビデオから2Dおよび3Dの特徴を抽出し、3Dオブジェクト中心の表現を構築します。
*   次に、提案されたパラメータ化された物理的先験モデル (PPPM) を使用して、この3D表現を洗練し、より正確で自然な3Dモーションシーケンスを生成します。

    *   人間の場合はSMPL-X、動物の場合はSMALといったパラメータ化された3Dモデルを使用し、3Dメッシュを復元します。一般的なオブジェクトには2.5D表現を用い、2Dバウンディングボックスと深度推定を組み合わせます。
    *   PPPMは、CLIPエンコーダーからのテキスト埋め込みと、隣接するフレーム間のパラメータ変化から計算されたモーション強度を使用して、モーションシーケンスを最適化します。PPPMは、自己注意、クロス注意、およびフィードフォワードネットワークを備えたトランスフォーマーアーキテクチャを採用しています。

**段階3: 洗練されたモーションシーケンスによるビデオの再生成**

*   最後に、この洗練されたモーションシーケンスを、追加の条件として同じビデオ拡散モデルにフィードバックし、複雑なアクションやインタラクションを含むシナリオでも、モーションの一貫性のあるビデオを生成できるようにします。モーションシーケンスから生成された部分セグメンテーションマスクとその信頼性マップを追加の条件チャネルとしてSVDに入力します。
*   この設計により、モデルは元の生成品質を維持し、ユーザー提供の入力からの逸脱を最小限に抑えながら、さまざまなタイプのモーションシーケンス入力に基づいてビデオを生成することができます。

## 3. 結果、何が達成できたのか

ReVision の導入により、以下の成果が得られました。

*   **モーションの忠実度と一貫性の向上:** ReVision は、Stable Video Diffusion (SVD) のモーションの忠実度と一貫性を大幅に向上させました。
*   **最先端モデルを凌駕する性能:** ReVision は、わずか 15 億のパラメータで、130 億以上のパラメータを持つ最先端のビデオ生成モデルを、複雑なビデオ生成において大幅に上回る性能を発揮しました。
*   **現実的なモーションとインタラクションの生成:** ReVision は、犬とのランニング、ボールを拾う、テニスボールを打つなど、複雑なモーションとインタラクションを含む高品質のビデオを生成できるようになりました。
*   **正確なモーション制御:** ReVision は、腕や手などの小さな体の部位の動きを正確に制御できるようになりました。
*   **人間らしいダンス動画の生成:** ダンス動画の生成において、ReVisionは、グランドトゥルースのポーズシーケンスに依存する既存の人間のイメージアニメーション手法を、すべての評価指標において上回る性能を達成しました。
*   **軽量かつ高速な推論:** 3段階のパイプラインにもかかわらず、3D検出とモーションの洗練モジュールを追加しても、A100 GPUでわずか5秒しか推論時間が追加されず、SVDよりも大幅に高速です。

## 4. Limitationや問題点は何か

ReVision には、以下の制限事項と問題点があります。

*   **オブジェクトカテゴリごとのモデルの必要性:** ReVision は、パラメータ化された 3D メッシュモデルに依存しているため、異なるオブジェクトカテゴリに対して複数の既製のモデルが必要になります。ただし、推論時間への影響は比較的小さいです。
*   **高画質な詳細の生成の難しさ:** ReVision は、指や手などの高画質な詳細を生成するのが難しい場合があります。
*   **メモリ制約によるビデオ長の制限:** 現在の実装は、バニラ SVD に基づいているため、メモリ制約 (80GB RAM) によりビデオ長が制限されています。PPPM は 32 フレームを超える現実的なモーションシーケンスを生成できますが、長尺ビデオ生成のための3D知識の探求は今後の課題となります。
*   **完全な自動化の欠如:** ReVision は、完全に自動化されたパイプラインではありません。特定のタスク（SMPL-XまたはSMALモデルの選択）において、人間の介入が必要となる場合があります。
*   **データセットへの依存性:** PPPM のトレーニングには、高品質でオブジェクト中心のアノテーションが施されたビデオデータセットが必要です。このタイプのデータセットは簡単に利用できるとは限りません。
*   **オブジェクトの3D構造の制約:** 現在のReVisionは、パラメータ化可能なオブジェクト(人間や動物)や、2.5Dで表現可能なオブジェクトに限定されており、完全に3Dの構造を持つ複雑なオブジェクトやシーンには適用が難しい場合があります。

## 5. 技術的な詳細について

ReVision の主要な技術的要素は以下の通りです。

*   **基盤モデル:** Stable Video Diffusion (SVD) を基盤として使用しています。SVD は、画像拡散モデルをビデオに拡張したもので、時間畳み込みと（クロス）注意レイヤーを空間レイヤーに追加することで時間的な一貫性を実現しています。
*   **モーション条件付きSVD:** 元のSVDに加えて、モーションシーケンスから派生したパートセグメンテーションマスクと、それに対応する信頼性マップという2つの追加条件チャネルをSVDの入力に追加しています。これにより、SVDはモーションに関する情報を取り入れ、より一貫性のあるビデオを生成できるようになります。
*   **パラメータ化された3Dオブジェクト表現:** 人間の場合は SMPL-X モデル、動物の場合は SMAL モデルを使用して、3D メッシュをパラメータ化します。汎用オブジェクトの場合は、2D バウンディングボックスと深度推定を組み合わせて 2.5D 表現を使用します。
*   **パラメータ化された物理的先験モデル (PPPM):** 粗いビデオから抽出された3Dモーションシーケンスを最適化するために、PPPMを導入しています。PPPMは、テキスト記述から抽出されたテキスト埋め込みと、モーションの強さを条件として、変換器アーキテクチャを使用してモーションシーケンスを反復的に洗練します。

PPPMのアーキテクチャは以下のようになります。

```python
class PPPM(nn.Module):
    def __init__(self, motion_dim, text_embedding_dim, num_layers, num_heads):
        super().__init__()
        self.motion_embedding = nn.Linear(motion_dim, motion_dim)
        self.transformer_blocks = nn.ModuleList([
            TransformerBlock(motion_dim, text_embedding_dim, num_heads) for _ in range(num_layers)
        ])
        self.output_layer = nn.Linear(motion_dim, motion_dim)

    def forward(self, motion_sequence, text_embedding, motion_strength):
        # motion_sequence: (batch_size, sequence_length, motion_dim)
        # text_embedding: (batch_size, text_embedding_dim)
        # motion_strength: (batch_size, 1)

        motion_embedding = self.motion_embedding(motion_sequence)
        x = motion_embedding

        for block in self.transformer_blocks:
            x = block(x, text_embedding, motion_strength)

        output = self.output_layer(x)
        return output

class TransformerBlock(nn.Module):
    def __init__(self, motion_dim, text_embedding_dim, num_heads):
        super().__init__()
        self.self_attention = nn.MultiheadAttention(motion_dim, num_heads)
        self.cross_attention = CrossAttention(motion_dim, text_embedding_dim, num_heads)
        self.feedforward = nn.Sequential(
            nn.Linear(motion_dim, motion_dim * 4),
            nn.ReLU(),
            nn.Linear(motion_dim * 4, motion_dim)
        )
        self.norm1 = nn.LayerNorm(motion_dim)
        self.norm2 = nn.LayerNorm(motion_dim)
        self.norm3 = nn.LayerNorm(motion_dim)

    def forward(self, x, text_embedding, motion_strength):
        # x: (batch_size, sequence_length, motion_dim)
        # text_embedding: (batch_size, text_embedding_dim)
        # motion_strength: (batch_size, 1)

        # Self-Attention
        attention_output, _ = self.self_attention(x, x, x)
        x = x + attention_output
        x = self.norm1(x)

        # Cross-Attention
        cross_attention_output = self.cross_attention(x, text_embedding, motion_strength)
        x = x + cross_attention_output
        x = self.norm2(x)

        # Feedforward Network
        feedforward_output = self.feedforward(x)
        x = x + feedforward_output
        x = self.norm3(x)

        return x

class CrossAttention(nn.Module):
    def __init__(self, motion_dim, text_embedding_dim, num_heads):
        super().__init__()
        self.query_projection = nn.Linear(motion_dim, motion_dim)
        self.key_projection = nn.Linear(text_embedding_dim, motion_dim)
        self.value_projection = nn.Linear(text_embedding_dim, motion_dim)
        self.attention = nn.MultiheadAttention(motion_dim, num_heads)
        self.motion_strength_projection = nn.Linear(1, 1) # Project motion_strength to a scalar

    def forward(self, x, text_embedding, motion_strength):
        # x: (batch_size, sequence_length, motion_dim)
        # text_embedding: (batch_size, text_embedding_dim)
        # motion_strength: (batch_size, 1)

        # Project motion_strength to a scalar
        motion_strength_scalar = self.motion_strength_projection(motion_strength)  # (batch_size, 1)

        # Apply motion_strength_scalar to the output of text_embedding, e.g., by multiplying the key/value projections
        query = self.query_projection(x) # (batch_size, sequence_length, motion_dim)
        key = self.key_projection(text_embedding.unsqueeze(1)) * motion_strength_scalar.unsqueeze(1)  # (batch_size, 1, motion_dim)
        value = self.value_projection(text_embedding.unsqueeze(1)) * motion_strength_scalar.unsqueeze(1) # (batch_size, 1, motion_dim)
        attention_output, _ = self.attention(query, key.expand(-1, x.shape[1], -1), value.expand(-1, x.shape[1], -1)) # (batch_size, sequence_length, motion_dim)
        return attention_output
```

*   **ファインチューニング戦略:** モーション条件付きビデオ生成のためにSVDをファインチューニングする際には、さまざまなレベルのパートマスクガイダンスを使用する3つのシナリオを統合しています。これにより、モデルはさまざまな入力に柔軟に対応できます。

# Llama-3.1-FoundationAI-SecurityLLM-Base-8B Technical Report

## 1. 既存研究では何ができなかったのか

既存研究における大規模言語モデル(LLM)のサイバーセキュリティ分野への応用は、以下の課題により限定的でした。

*   **専門的な訓練データの不足:** サイバーセキュリティ固有の知識を学習させるための高品質なデータセットが不足していました。既存のデータセットは、ノイズが多い、網羅性が低い、またはアクセスが制限されているなどの問題がありました。

## 5. 技術的な詳細について

### SFT（教師ありファインチューニング）

SFTでは、推論能力を持つ教師モデル（DeepSeek-R1など）から生成された推論トレース（Chain-of-Thoughts: CoT）を含むデータセットを用いて、ベースモデルをファインチューニングします。重要なポイントは以下の通りです。

*   **データセット構築**:
    *   多様なドメイン（数学、科学、コーディング、パズルなど）からの問題収集。
    *   重複排除 (embedding similarity, n-gram など)。
    *   リジェクションサンプリングによる品質向上。
    *   教師モデルによる CoT 生成と検証 (Math Verify, コード実行テスト, LLM Judge など)。
    *   難易度と多様性のバランスを考慮したデータ選択。
*   **学習設定**:
    *   RoPEスケーリングファクタ (RoPE scaling factor) の調整によるコンテキスト長の拡張 (32,768 tokens)。
    *   学習率 (1.0e-5 ~ 5.0e-5) とバッチサイズ (96 or 128) の設定。
    *   パッキングによる学習効率の向上。

### RLVR（検証可能な報酬からの強化学習）

RLVRでは、推論タスクに対する報酬を定義し、強化学習アルゴリズム (PPO, GRPO など) を用いてモデルを最適化します。

*   **データセット構築**:
    *   数学、コーディングなどの検証可能なタスクに特化したデータセット。
    *   データの選択、検証可能な質問と回答の作成、詳細な前処理手順を含むキュレーション。
    *   データの品質、多様性、量に注目。
*   **アルゴリズム**:
    *   PPO (Proximal Policy Optimization) をベースに、様々な改良が施されています。
    *   GRPO (Group Relative Policy Optimization): PPOの効率的なバリエーションで、criticモデルとGAE計算を省略し、報酬の分散を減らすためにグループ内で報酬を正規化します。
    *   KL-divergence ペナルティによるポリシーの安定化。
    *   DAPO (Decoupled Clip and Dynamic sAmpling Policy Optimization): エントロピー崩壊、学習の不安定性、バイアスされた損失などの問題を解決するために、クリップ範囲の調整やダイナミックサンプリングなどの手法を導入。
    *   報酬関数は、精度、フォーマット、長さなどを考慮して設計。

#### PPOの疑似コード

```python
# θ: モデルのパラメータ
# φ: criticモデルのパラメータ
# D: データセット
# π_old: 古いポリシー

for (q, a) in D: # q: 質問、a: 正解
  o = π_old(q)  # ロールアウト生成
  r = reward(o, a)  # 報酬計算

  # GAE (Generalized Advantage Estimation) の計算
  V = critic(o, φ)
  advantage = r - V

  # PPOの損失関数
  loss = min(
    ratio(o, π_old, θ) * advantage,
    clip(ratio(o, π_old, θ), 1-epsilon, 1+epsilon) * advantage
  )

  # モデルの更新
  θ = θ - learning_rate * gradient(loss, θ)
  φ = φ - learning_rate * gradient((r - V)**2, φ)

def ratio(o, π_old, θ):
  # 現在のポリシーと古いポリシーの確率の比
  return π(o | q, θ) / π_old(o | q)

def clip(x, low, high):
  # クリップ関数
  return max(low, min(x, high))

def reward(o, a):
  # 報酬関数 (例: 正解なら1、不正解なら0)
  if o == a:
    return 1
  else:
    return 0

def critic(o, φ):
    # criticモデルによる価値予測
    return value(o, φ)
```

## 5. 技術的な詳細について

UniBiomedは、MLLMとSAMを統合したアーキテクチャに基づいています。

1.  **MLLM:**
    *   **Vision Encoder:** 画像をビジュアルトークンにエンコードします。InternVL2.5をベースにしています。
    *   **Large Language Model (LLM):** テキストを言語トークンに処理し、ビジュアルトークンと組み合わせてテキスト出力を生成します。
2.  **SAM:**
    *   **Vision Encoder:** 画像の特徴を抽出します。SAM2をベースにしています。
    *   **Prompt Encoder:** MLLMからの言語埋め込みとユーザー指示をエンコードし、テキストガイドセグメンテーションを可能にします。
    *   **Mask Decoder:** セグメンテーションマスクを生成します。

**学習プロセス:**

*   **損失関数:** テキスト生成損失 (L\_text) とセグメンテーション損失 (L\_seg) の組み合わせを使用します。

    ```python
    L = L_text + L_seg
    L_seg = 2 * L_BCE + 0.5 * L_dice
    ```

    *   L\_BCE は、ピクセルごとの二項交差エントロピー損失です。

        ```python
        L_BCE = - (1/N) * sum([y_i * log(p_i) + (1 - y_i) * log(1 - p_i) for i in range(N)])
        ```

    *   L\_dice は、Dice損失です。

        ```python
        L_dice = 1 - (2 * sum([p_i * y_i for i in range(N)]) + epsilon) / (sum([p_i for i in range(N)]) + sum([y_i for i in range(N)]) + epsilon)
        ```

        ここで、`y_i` はグラウンドトゥルース、`p_i` は予測確率、`N` はピクセル数、`epsilon` は数値安定性のための小さな定数です。
*   **ファインチューニング:** InternVL2.5のビジョンエンコーダを凍結し、LoRA（Low-Rank Adaptation）を使用して効率的なファインチューニングを実行します。SAM2のビジョンエンコーダを凍結し、プロンプトエンコーダとマスクデコーダのみをファインチューニングします。
*   **プロンプト:** テキストプロンプトを使用して、SAMのマスクデコーダをガイドします。特定のトークン`[SEG]`を使用して、セグメンテーションマスクの生成を指示します。

# Selecting Optimal Candidate Profiles in Adversarial Environments Using Conjoint Analysis and Machine Learning

[View Paper](http://arxiv.org/abs/2504.19043v1)

## 1. 既存研究では何ができなかったのか

既存のConjoint分析研究、特に政治分野での候補者選択の分析において、以下の点が不十分でした。

*   **戦略的相互作用の欠如:** 従来のConjoint分析では、対立候補の特徴がランダムに選択されるという非現実的な仮定に基づいていました。実際の選挙では、政党や候補者は、勝利の可能性を最大化するために戦略的に候補者を選択します。この戦略的な相互作用（adversarial setting）が考慮されていませんでした。
*   **最適な候補者プロファイルの特定:** 既存研究は主に、各属性の平均因果効果 (Average Marginal Component Effect, AMCE) の推定に焦点を当てており、最適な候補者プロファイルの特定は考慮されていませんでした。
*   **高次元性への対応:** Conjoint分析では、特徴量の組み合わせ数がサンプルサイズを大幅に上回ることが一般的です。そのため、観測データから直接最適なプロファイルを決定することは不可能でした。既存研究では、この高次元性の問題に対する直接的なアプローチがありませんでした。
*   **政策学習との連携:** 政策学習の分野では、二値または少数の処置の最適化に焦点が当てられており、Conjoint分析のような高次元の処置空間での最適化はほとんど研究されていませんでした。

## 2. どのようなアプローチでそれを解決しようとしたか

論文では、上記の課題を解決するために、Conjoint分析に以下の要素を組み込みました。

*   **敵対的環境の導入:** 政党や候補者が、選挙での勝利確率を最大化するために、互いに対立する戦略的な環境をモデル化しました。具体的には、候補者プロファイルが2段階の競争に直面するモデルを構築しました。一次予備選挙での党内競争と、本選挙での党間競争です。
*   **確率的介入の最適化:** サンプルサイズが特徴量の組み合わせ数を大幅に下回るという問題に対処するために、固定された最適な処置を探索する代わりに、候補者の特徴の確率分布を表す最適な確率的介入 (optimal stochastic intervention) を導出しました。これにより、優れたパフォーマンスを示す可能性のある候補者の特徴をより適切に特定できます。
*   **正則化:** 学習されたプロファイル分布の分散が過度に大きくならないように、正則化 (regularization) を適用しました。これにより、過剰適合 (overfitting) を防ぎ、モデルの汎化性能を高めています。
*   **デルタ法:** モデルの不確実性を定量化し、最適な戦略の推定における信頼区間を計算するために、デルタ法 (Delta method) を適用しました。
*   **共変量に基づく戦略:**  個々の回答者の特性を考慮した、条件付き確率分布を推定するフレームワークを提案しています。

## 3. 結果、何が達成できたのか

論文では、提案手法を米大統領選挙の候補者選択に関する既存のConjoint分析データに適用し、以下の成果を達成しました。

*   **現実的な予測の改善:** 敵対的競争を考慮したモデルは、実際の選挙結果に近い、より現実的な投票シェアの予測を提供しました。
*   **実際の候補者との整合性向上:** 提案手法によって示唆される最適な戦略は、敵対的設定を考慮しないアプローチと比較して、実際に観測された候補者とより一致する可能性が高くなりました。
*   **共和党候補者の戦略的一致:** 2016年の選挙では、共和党候補者の特徴が、推定された戦略とより密接に一致していることがわかりました。
*   **候補者レベルでの戦略的乖離の定量化:** 実際の候補者情報と実験結果を用いて、戦略的乖離 (strategic divergence) を測定する手法を開発しました。
*   **共変量に基づいた分析:** 共変量を用いた分析により、民主党、共和党、無党派層のクラスタリング構造を回復することができました。

## 4. Limitationや問題点は何か

論文で言及されている制限事項：

*   **モデルの複雑性:** より複雑なoutcomeモデル（３次以上の交互作用）に対しては、解析的な解が得られず、計算コストが増大します。
*   **非負制約:** 確率変数の合計が1になる制約を維持しながら確率を計算する際、負の値が発生する可能性があります。

私が考える制限事項と問題点：

*   **SUTVA (Stable Unit Treatment Value Assumption) の仮定:** 個々の回答者の選好は固定されている前提ですが、実際の選挙では、候補者のレトリックや政治マーケティングを通じて変化する可能性があります。
*   **制度設計の特定:** 最適な戦略は制度設計に依存しますが、制度設計の定量化が難しい場合があり、分析結果が主観的になる可能性があります。
*   **計算コスト:** 敵対的環境における最適化計算は、計算コストが高い可能性があります。特に、特徴量の数が多い場合や、複雑な制度設計を考慮する場合に顕著です。
*   **偏ったサンプル:** 実験参加者が一般投票者を代表しているかどうかの問題があります。 Conjoint分析の結果の妥当性は、サンプルが母集団をどれだけ代表しているかに依存します。
*   **戦略のダイナミズムの欠如:** モデルは、選挙キャンペーン中の戦略のダイナミックな調整を捉えていません。
*   **単純化された選好:** Conjoint分析で得られた選好が、実際の投票行動を正確に反映しているとは限りません。回答者は、実験環境下での選択と、実際の投票時の選択で異なる基準を用いる可能性があります。

## 5. 技術的な詳細について

提案手法の技術的な詳細は以下の通りです。

1.  **モデルの定式化:**
    *   Conjoint分析の結果から、候補者プロファイルの特徴に基づいた効用関数を学習します。
    *   敵対的環境下での候補者選択を、2人ゼロサムゲームとしてモデル化します。
    *   各候補者は、自身の勝利確率を最大化するような候補者プロファイルの確率分布を戦略として選択します。
    *   最適な確率的介入を求めるために、以下の目的関数を最適化します。

    ```python
    def objective_function(pi, Y, T, p, lambda_n):
        """
        目的関数を計算する

        Args:
            pi: 候補者の特徴の確率分布（戦略）
            Y: 観測された結果
            T: 提示された候補者プロファイル
            p: データ生成分布（一様分布など）
            lambda_n: 正則化パラメータ

        Returns:
            最適化する目的関数の値
        """
        Q = calculate_average_outcome(pi, Y, T)  # 平均結果の計算
        regularization_term = lambda_n * l2_norm(pi, p) # L2正則化項の計算

        return Q - regularization_term
    ```

2.  **確率的介入の最適化:**
    *   解析的に解を求めることが難しい場合、勾配上昇法などの数値最適化手法を用いて確率分布`pi`を探索します。

    ```python
    def gradient_ascent(objective_function, initial_pi, learning_rate, iterations, Y, T, p, lambda_n):
        """
        勾配上昇法を用いて、確率分布piを最適化する。

        Args:
            objective_function: 最適化する目的関数
            initial_pi: 初期確率分布
            learning_rate: 学習率
            iterations: 勾配上昇法の反復回数

        Returns:
            最適化された確率分布
        """
        pi = initial_pi
        for i in range(iterations):
            gradient = calculate_gradient(objective_function, pi, Y, T, p, lambda_n) # 目的関数の勾配を計算
            pi = update_pi(pi, gradient, learning_rate) # 確率分布を更新

        return pi
    ```

3.  **正則化:**
    *   L2正則化を用いて、過剰適合を抑制し、汎化性能を高めます。
    *   正則化パラメータ`lambda_n`は、交差検証 (cross-validation) などの手法を用いて適切に設定します。

4.  **制度的な制約の組み込み:**
    *   予備選と本選という2段階の選挙プロセスをモデル化します。
    *   各段階での候補者の選好と制度的なルールを考慮して、期待される投票シェアを計算します。

5.  **推論:**
    *   デルタ法を用いて、モデルのパラメータ推定における不確実性を考慮し、最適な戦略における信頼区間を計算します。

## 5. 技術的な詳細について

生成AI for Character Animation の技術的な詳細について解説します。

1.  **SMPL (Skinned Multi-Person Linear Model)**
    *   3D人体形状とポーズのパラメータモデルです。
    *   形状パラメータ `β` は、平均的な人体形状からの偏差を表現します。PCA（主成分分析）によって学習された形状空間を利用します。
    *   ポーズパラメータ `θ` は、関節の回転を表現します。各関節は指数写像で回転行列に変換され、線形ブレンドスキニングで使用されます。
    *   これにより、コンパクトかつ制御可能な人体表現が可能になります。

    ```python
    def smpl(beta, theta):
        # beta: 形状パラメータ (テンソル)
        # theta: ポーズパラメータ (テンソル)

        # 平均形状 + 形状偏差
        verts = mean_shape + blend_shapes(beta)

        # 関節回転の計算
        rotations = axis_angle_to_rotation_matrix(theta)

        # 線形ブレンドスキニング
        verts_deformed = linear_blend_skinning(verts, rotations, bone_weights)

        return verts_deformed
    ```

2.  **GAN (Generative Adversarial Networks)**
    *   Generator（生成器）と Discriminator（識別器）の2つのネットワークが競合しながら学習します。
    *   Generator は、ランダムノイズからリアルなデータを生成するように学習します。
    *   Discriminator は、入力データが本物か生成されたものかを識別するように学習します。
    *   学習は以下の minimax game で表現されます。

    ```python
    def gan_loss(real_data, generated_data, discriminator):
        # 識別器の損失 (本物と偽物を識別)
        real_loss = log(discriminator(real_data))
        fake_loss = log(1 - discriminator(generated_data))

        # 生成器の損失 (識別器を騙す)
        generator_loss = -log(discriminator(generated_data)) # または 1- discriminator(generated_data)を最小化

        return real_loss, fake_loss, generator_loss
    ```

3.  **VAE (Variational Autoencoder)**
    *   Encoder (エンコーダ) は、入力データを潜在空間の分布に変換します（平均 `μ` と分散 `σ` ）。
    *   Decoder (デコーダ) は、潜在空間から元のデータを再構成します。
    *   潜在空間に正則化項（KLダイバージェンス）を加えることで、連続的で意味のある潜在空間を学習します。

    ```python
    def vae_loss(data, encoder, decoder, kl_weight=0.01):
        # エンコーダから潜在変数の分布パラメータを取得
        mu, log_sigma = encoder(data)
        sigma = exp(log_sigma)

        # Reparameterization trick (勾配計算を可能にするため)
        epsilon = torch.randn_like(sigma) # 標準正規分布からのサンプル
        z = mu + epsilon * sigma

        # デコーダから再構成されたデータ
        reconstructed_data = decoder(z)

        # 再構成損失
        reconstruction_loss = mse_loss(data, reconstructed_data)

        # KLダイバージェンス (潜在分布を標準正規分布に近づける)
        kl_loss = -0.5 * torch.sum(1 + log_sigma - mu**2 - sigma**2, dim=1).mean()

        # 合計損失
        total_loss = reconstruction_loss + kl_weight * kl_loss

        return total_loss, reconstruction_loss, kl_loss
    ```

4.  **DDPM (Denoising Diffusion Probabilistic Models)**
    *   フォワード拡散過程で、データに徐々にノイズを加えていき、最終的にガウスノイズにします。
    *   リバース過程では、学習されたモデル（通常は U-Net）を使って、ノイズを除去して元のデータを再構成します。

    ```python
    def ddpm_loss(model, x_0, t, noise=None):
        # x_0: 元のデータ
        # t: タイムステップ
        # model: ノイズ予測モデル
        # noise: ノイズ (通常は標準正規分布からサンプリング)

        if noise is None:
            noise = torch.randn_like(x_0)

        # 拡散過程でノイズを加えたデータ
        x_t = q_sample(x_0, t, noise=noise) # q_sampleは拡散過程の関数

        # モデルによるノイズの予測
        predicted_noise = model(x_t, t)

        # 損失 (予測ノイズと実際のノイズの差)
        loss = mse_loss(noise, predicted_noise)

        return loss
    ```

5.  **Transformer**
    *   EncoderとDecoderで構成され、Self-Attention機構を用いて、系列データの長距離依存関係を捉えます。
    *   Self-Attention は、Query, Key, Value の3つの要素から計算され、入力系列内の各要素が他の要素にどれだけ注意を払うかを決定します。

    ```python
    def scaled_dot_product_attention(Q, K, V, mask=None):
        # Q: Query
        # K: Key
        # V: Value
        # mask: (オプション) attention スコアに適用するマスク

        d_k = K.size(-1)
        attention_scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(d_k)

        if mask is not None:
            attention_scores = attention_scores.masked_fill(mask == 0, -1e9)  # マスクされた位置は非常に小さい値にする

        attention_weights = torch.softmax(attention_scores, dim=-1)
        output = torch.matmul(attention_weights, V)

        return output, attention_weights
    ```

# Beyond the Last Answer: Your Reasoning Trace Uncovers More than You Think

[View Paper](http://arxiv.org/abs/2504.20708v1)

## 1. 既存研究では何ができなかったのか

既存研究では、LLMによる推論の評価において、生成された推論トレースの**最終的な回答の正誤のみに焦点を当てていた**。これは、最終的な回答がモデルの最適な結論を常に正確に反映しているとは限らず、異なる推論パスが異なる結果をもたらす可能性があるという問題を見過ごしていた。つまり、推論の過程にある**中間的な推論ステップ（subthought）**に着目することで、最終的な回答だけでは捉えられないモデルの潜在的な能力や誤りを検出できる可能性を考慮していなかった。

## 2. どのようなアプローチでそれを解決しようとしたか

本研究では、以下のステップで問題を解決しようとした。

1.  **Subthoughtの抽出:** 推論トレースを、言語的な手がかりに基づいて連続したsubthoughtに分割する。
2.  **継続の生成:** 各subthoughtの終点から、モデルに推論を継続させる。
3.  **回答の抽出:** 各継続から、潜在的な回答を抽出する。
4.  **回答の集約:** 異なるsubthoughtから得られた回答を集約し、最頻値（mode）を選択することで、より正確な回答を得ることを目指す。
5.  **一貫性の分析:** 異なるsubthoughtから得られた回答の一貫性を分析し、モデルの確信度や正答率との相関関係を調べる。

疑似コードで表すと以下のようになる:

```python
def subthought_reasoner(reasoning_trace):
    # 1. Subthoughtの抽出
    subthoughts = segment_into_subthoughts(reasoning_trace)

    potential_answers = []
    for subthought in subthoughts:
        # 2. 継続の生成
        continuations = generate_continuations(subthought)

        for continuation in continuations:
            # 3. 回答の抽出
            answer = extract_answer(continuation)
            potential_answers.append(answer)

    # 4. 回答の集約
    aggregated_answer = calculate_mode(potential_answers)

    # 5. 一貫性の分析 (概要)
    consistency = calculate_consistency(potential_answers)
    # 例えば、回答の分散やエントロピーを計算する

    return aggregated_answer, consistency
```

## 3. 結果、何が達成できたのか

実験の結果、提案手法を用いることで、最終的な回答のみに頼る場合に比べて、**一貫して精度が向上**した。特に、AIME2024およびAIME2025といった難易度の高い数学的推論データセットにおいて、それぞれ最大で13%および10%の精度向上が見られた。これは、中間的な推論ステップを分析し、複数の推論パスから得られた回答を集約することで、モデルの潜在的な能力を引き出し、誤りを修正できることを示唆している。また、回答の一貫性を分析することで、モデルの確信度や正答率を予測できる可能性も示唆された。

## 4. Limitationや問題点は何か

*   **Subthoughtの分割方法:** 言語的な手がかりに基づいてsubthoughtを分割する手法は、必ずしも最適な分割を保証するものではない。より高度な分割手法（意味解析に基づくなど）が必要になる可能性がある。
*   **継続の生成:** 各subthoughtから生成する継続の数や生成戦略が、結果に影響を与える可能性がある。適切な数の継続を生成し、多様な推論パスを探索する必要がある。
*   **回答の抽出:** 継続から回答を抽出するプロセスは、エラーが発生しやすい。自然言語処理技術を用いて、より正確に回答を抽出する必要がある。
*   **計算コスト:** 各subthoughtから複数の継続を生成し、それぞれから回答を抽出するため、計算コストが増加する。
*   **汎用性:** AIMEのような数学の問題に特化したデータセットでの評価が中心であり、他の種類の推論タスクに対する汎用性は不明。
*   **モデル依存性:** 実験に使用されたLLMに結果が依存する可能性があり、異なるモデルアーキテクチャやスケールで同様の結果が得られるとは限らない。
*   **理論的根拠:** なぜこの手法が有効なのか、理論的な裏付けが不足している。

**私が考える問題点:**

*   **ノイズ:** 生成される継続の中には、無関係な情報やノイズが含まれる可能性がある。これらのノイズが、回答の集約を妨げる可能性がある。
*   **敵対的な攻撃:** 悪意のある入力によって、意図的に誤ったsubthoughtを生成させ、最終的な回答を誤らせる可能性がある。

# WebThinker: Empowering Large Reasoning Models with Deep Research Capability

[View Paper](http://arxiv.org/abs/2504.21776v1)

## 1. 既存研究では何ができなかったのか

既存の大規模推論モデル (LRMs) は、長期的な推論能力において目覚ましい成果を示していますが、以下の点で限界があります。

*   **静的な内部知識への依存:** 複雑で知識集約型のタスクにおいて、そのパフォーマンスは静的な内部知識に大きく依存しており、最新の情報や特定のドメインに関する深い知識を必要とする場合に性能が低下します。
*   **包括的な研究レポートの作成能力の欠如:** 多様なウェブ情報を統合して包括的な研究レポートを作成する能力が不足しています。リアルタイムでウェブを検索し、情報を整理・統合してレポートを作成することができません。
*   **動的な情報収集能力の欠如:** ナレッジギャップに遭遇した場合に、自律的にウェブを検索し、必要な情報を収集する能力が不足しています。

## 2. どのようなアプローチでそれを解決しようとしたか

WebThinkerは、上記の問題点を解決するために、以下の3つの主要なモジュールと戦略を導入しました。

*   **Deep Web Explorer:** 大規模推論モデル (LRMs) が、知識のギャップに遭遇した際に動的にウェブを検索、ナビゲート、情報抽出できるようにするモジュールです。
*   **Autonomous Think-Search-and-Draft strategy:** 推論、情報収集、レポート作成をリアルタイムでシームレスに連携させることを可能にする戦略です。モデルが思考プロセスの中で必要に応じて検索を行い、草稿を作成します。
*   **RL-based training strategy:** 反復的なオンライン Direct Preference Optimization (DPO) を介して、研究ツールの利用をさらに強化するための強化学習 (RL) に基づくトレーニング戦略です。

これらの要素を組み合わせることで、WebThinkerはLRMの能力を拡張し、より複雑なタスクに対応できるようにしました。

## 3. 結果、何が達成できたのか

WebThinkerは、以下の点で既存手法および強力なプロプライエタリシステムを大幅に上回る性能を達成しました。

*   **複雑な推論ベンチマークでの性能向上:** GPQA、GAIA、WebWalkerQA、HLEといった複雑な推論ベンチマークにおいて、既存手法を大幅に上回る性能を示しました。
*   **科学レポート生成タスクでの性能向上:** Glaiveといった科学レポート生成タスクにおいて、既存手法を大幅に上回る性能を示しました。
*   **LRMの信頼性と応用性の向上:** WebThinkerのアプローチにより、LRMはより信頼性が高く、複雑なシナリオでの応用性が向上しました。

これにより、WebThinkerは、より高性能で汎用性の高い深層研究システムの実現に貢献しています。

## 4. Limitationや問題点は何か

論文で明示的に言及されている制限事項はありません。ただし、以下の点が考えられます。

*   **ウェブ検索のノイズへの対応:** ウェブ検索結果にはノイズが多く含まれるため、Deep Web Explorerが関連性の高い情報のみを効率的に抽出できるかどうかが課題となります。検索クエリの最適化や、不要な情報のフィルタリングが重要です。
*   **計算コスト:** 大規模な言語モデルを使用し、リアルタイムでウェブ検索を行うため、計算コストが高くなる可能性があります。特に、強化学習を用いたトレーニングには、多くの計算リソースが必要となる可能性があります。
*   **偏った情報源への依存:** ウェブ検索結果は、情報源の偏りやバイアスを含む可能性があります。WebThinkerが生成するレポートの客観性を保証するためには、多様な情報源を考慮し、バイアスを軽減するメカニズムが必要です。
*   **倫理的な問題:** 自動的なウェブ検索とレポート作成は、プライバシー侵害や誤情報の拡散といった倫理的な問題を引き起こす可能性があります。適切な監視と制御メカニズムが必要です。
*   **汎用性:** 実験で使用されたタスク以外のタスクに対する汎用性が不明です。異なるドメインやタスクに適用する場合、追加のチューニングや調整が必要になる可能性があります。

*   **Deep Web Explorer:**

    *   **ウェブページナビゲーション:** 取得した検索結果から、関連性の高いウェブページを特定し、Seleniumなどのツールを用いてウェブページをナビゲートします。

        def navigate_webpage(url):
            # Selenium を用いてウェブページを読み込む
            driver = webdriver.Chrome()
            driver.get(url)

    *   **情報抽出:** ウェブページの内容を解析し、必要な情報を抽出します。BeautifulSoupなどのHTMLパーサーや、正規表現、自然言語処理技術などを組み合わせて利用します。
        ```python
        def extract_information(html_content, keywords):
            # BeautifulSoup を用いて HTML を解析
            soup = BeautifulSoup(html_content, 'html.parser')
            # キーワードに関連するテキストを抽出
            relevant_text = soup.find_all(text=lambda text: any(keyword in text for keyword in keywords))
            return relevant_text
        ```

*   **Autonomous Think-Search-and-Draft strategy:**
    *   **推論モジュール:** 大規模言語モデル (例: OpenAI-o1, DeepSeek-R1) を利用して、タスクの分解、検索クエリの生成、情報の統合、レポートの作成を行います。
    *   **思考プロセス:**
        1.  **Task Decomposition:** 複雑なタスクをより小さなサブタスクに分解します。
        2.  **Query Generation:** 各サブタスクに必要な情報を得るための検索クエリを生成します。
        3.  **Information Retrieval:** Deep Web Explorerを用いて、生成された検索クエリに基づいてウェブ検索を行い、関連情報を収集します。
        4.  **Information Integration:** 収集した情報を統合し、矛盾や重複を解消します。
        5.  **Report Drafting:** 統合された情報に基づいて、レポートの草稿を作成します。
    *   上記のステップを繰り返しながら、レポートを段階的に改善していきます。

*   **RL-based training strategy:**
    *   **Direct Preference Optimization (DPO):** 強化学習を用いて、モデルの行動を最適化します。
        *   **報酬関数:** レポートの品質、関連性、正確性などを評価するための報酬関数を定義します。
        *   **オンライン学習:** リアルタイムで生成されたレポートに対するフィードバックに基づいて、モデルを継続的に学習させます。
        ```python
        def dpo_training(model, data, reward_function):
            # DPO アルゴリズムを用いてモデルをトレーニング
            for episode in data:
                # モデルの出力（レポート）を生成
                report = model.generate_report(episode['task'])
                # 報酬を計算
                reward = reward_function(report)
                # モデルを更新
                model.update(reward)
            return model
        ```
